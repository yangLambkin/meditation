## 用户需求

- recorder 页已将原五星评分 UI 替换为「情绪选择」，`getSelectedEmotions()` 返回字符串数组（选了子情绪则为子情绪名数组，否则为 `[主情绪名]`）。
- 需要将「情绪」存入用户每次打卡记录 `meditation_records`（以 `emotion` 字段承载），并彻底去掉 `rating` 逻辑。
- 必须包含数据库（云开发文档库）修改方案：含字段定义更新与存量数据迁移。

## 核心要点

- 当前情绪数据实际上已借道 `rating` 通道写入（recorder → checkin → cloudApi → meditationManager → `meditation_records.rating`），因此线上 `rating` 字段存的已是字符串数组，与 schema 注释「1-5 星」不一致。
- 本次改造本质是把 `rating` 字段**改名为 `emotion`**（数组 of string），并清除所有 rating 相关逻辑与死字段。
- 数据库为 schemaless 文档库，「改数据库」= 更新 schema 定义生成器 + 跑一次性迁移脚本对存量记录做字段改名。

## 技术栈

- 微信小程序（CommonJS，2 空格无分号）+ 云开发云函数（`meditationManager` 单 dispatch 模式）。
- 数据库：云开发文档型 DB，无强制 schema；所谓 schema 仅存在于 `autoCreateCollections`、`create_collections_consistent.js` 的样例数据生成器与文档约定。

## 实现方案

### 总体策略

全链路将 `rating` 语义替换为 `emotion`（类型：`string[]`，如 `['平静','感恩']` 或 `['不悲不喜']`），采用「先加新字段、保留旧字段做兼容、再迁移存量、最后清理旧字段」的平滑路径，避免发布期客户端/云端版本不一致导致数据丢失。

### 关键决策与理由

1. **云端写入双兼容**：`meditationManager.recordMeditation` 改为写入 `emotion`，取值优先级 `data.emotion || data.rating || []`（兼容尚未更新的旧客户端仍发 `rating`）。理由：小程序发版与云函数部署存在时间差，兼容读取可防止过渡期数据丢失。
2. **前端链路重命名**：`recorder.js` → `checkin.js(recordCheckin/recordToLocal/asyncBackupToCloud/formatCloudRecord/rebuildLocalCacheFromCloudRecords/同步循环)` → `cloudApi.recordMeditation` 统一将参数与字段名 `rating` 改为 `emotion`。
3. **history 页去星逻辑**：原 5 星渲染 `i < (record.rating||0)` 因 rating 已是数组而失效，改为渲染 `emotion` 标签；`history.js` 输出 `emotions` 数组，`.wxml` 用标签展示替代星星。
4. **删除死字段**：`create_collections_consistent.js` 中 `experience_records.rating` 是未写入的死字段（运行时 `saveExperienceRecord` 不写 rating），一并移除。
5. **存量数据迁移**：新建一次性云函数 `migrateRatingToEmotion`，遍历 `meditation_records`，对存在 `rating` 且缺 `emotion` 的记录：`emotion = Array.isArray(rating) ? rating : []`，随后 `db.command.remove` 删除 `rating` 字段；已含 `emotion` 的跳过。运行前/后打印计数核对。

### 性能与可靠性

- 迁移脚本分批（limit 100）游标遍历，避免一次性拉取全部文档；仅改真正缺 `emotion` 的记录，幂等可重跑。
- 兼容读取保证发布窗口期零数据丢失；迁移完成后旧 `rating` 字段清除，schema 与运行时完全一致。

## 数据库修改 Plan

### A. 字段定义更新（样例/约定）

- `cloudfunctions/autoCreateCollections/index.js`：`meditation_records.sampleData` 将 `rating: 4` 改为 `emotion: ['不悲不喜']`（注释改为「情绪标签数组」）。
- `create_collections_consistent.js`：`meditation_records.fields` 将 `rating: 'number'` 改为 `emotion: 'array'`；`sampleData.rating = 4` 改为 `sampleData.emotion = ['不悲不喜']`；删除 `experience_records.fields.rating`。

### B. 存量数据迁移（一次性）

- 新建云函数 `migrateRatingToEmotion`（参照 `autoCreateCollections` 的 one-shot 模式），按上述逻辑将 `rating` 迁至 `emotion` 并删 `rating`。
- 执行：微信开发者工具上传该云函数后调用一次；先 `count` 含 `rating` 的记录数，迁移后再次核对，确认 `emotion` 写入且 `rating` 清零。

### C. 写入兼容

- `recordMeditation` 取值 `data.emotion || data.rating || []`，过渡期无缝。

## 关键代码结构（迁移云函数核心）

```js
// cloudfunctions/migrateRatingToEmotion/index.js
exports.main = async () => {
  const db = cloud.database();
  const _ = db.command;
  let migrated = 0, skipped = 0;
  // 分批游标遍历 meditation_records
  const res = await db.collection('meditation_records')
    .where({ rating: _.exists(true) }).limit(100).get();
  for (const doc of res.data) {
    if (Array.isArray(doc.emotion) && doc.emotion.length) { skipped++; continue; }
    const emotion = Array.isArray(doc.rating) ? doc.rating : [];
    await db.collection('meditation_records').doc(doc._id).update({
      data: { emotion, rating: _.remove() }
    });
    migrated++;
  }
  return { success: true, migrated, skipped };
};
```
