# 必经之路绑定与同步

本说明保留接入入口和验证要点。旧版每五分钟续跑、固定四轮重试与固定 60 秒时限的方案已被持久恢复取代；当前任务、索引与部署顺序以[批量同步](../docs/2026-09-23-admin-batch-sync.md)、[自动恢复](../docs/2026-10-10-auto-sync-recovery.md)和[运维权限](../docs/maintenance-access.md)为准。

## 调用边界

- `miniprogram/utils/bijingApi.js` 封装绑定、校验、个人日期预览与同步；微信云端 `bijingSync` 负责静坐日汇总、批量上报、核对和恢复。
- 微信静坐同步以云端 `meditation_records` 为事实来源，按北京时间 `[当天 02:00, 次日 02:00)` 汇总有效时长；手动记录保留所选业务日，无可靠时间的旧记录保留合法日期。
- 同步必经不隐式补传本机记录。选择日期尚有待上传记录时先等待/处理上传；补传成功不等于对端日汇总已确认。
- 热力图、新功课与 data 团队由小程序直连 OpenAPI，分别见 [热力图](../docs/heatmap-openapi.md)、[功课记录](../docs/2026-10-31-practice-records.md)、[团队接入](../docs/team-openapi.md)。它们与微信云端同步是不同调用路径。

## 绑定与个人同步

绑定注册表保证一个学号只有一个有效微信绑定。管理员权限基于中央唯一有效绑定；解绑保留原账号历史及归档，不自动迁移给新账号。绑定时可使用对端有效昵称更新资料，空昵称不应覆盖已有值。迁移已有唯一绑定见 [绑定迁移说明](../docs/2026-09-23-binding-migration.md)。

个人入口先通过 `getSyncDateDetails` 预览，再通过 `syncSelectedDate` 同步所选日期；只允许最近七个已结束业务日，服务端重新校验范围。预览与发送都重新读取真实源记录，不能信任页面旧总量。切换日期、关闭弹窗或账号变化后丢弃旧请求结果。

`users.bijingSyncedDates` 表示历史成功状态，不能据此跳过当前版本的核对。暂时查询不到记录、查询失败、上传响应丢失和实际归零是不同情况；已结束日期的新增、补传、修改和删除通过持久待办恢复，已确认清零也须有真实源变更依据。

## 环境与验证

`bijingSync` 的 `BIJING_API_BASE`、`BIJING_ACCESS_TOKEN` 在对应云环境配置；测试基地址为 `https://data.bjzl.net.cn`，生产为 `https://data.bijing.life`。令牌以部署配置为准。直连客户端另有环境配置，修改云端地址不会自动切换功课、团队或热力图的目标环境。

原生定时器要求 `BIJING_TIMER_ENABLED=true` 与 `BIJING_TIMER_SOURCE=wx_trigger`，来源由平台上下文确认。实际执行时限和索引须读取环境核验，历史发布记录不能替代当前配置。当前调度为 02:00 上传、03:00–10:00 整点核对修复，未完成任务跨日保留。

验收包括：绑定/解绑及唯一性、普通用户与管理员权限、01:59/02:00 分界、原始记录分页、离线补传、同日再次修改、删除后归零、超时回查、账号切换和旧回包、错误跨日恢复。以对端实际总量与本地/云端任务确认状态共同判断结果，顶层 `success:true` 不代表整批已经同步完成。

本地可运行 `npm run test:bijing-sync` 和 `npm run test:backfill`；真实平台身份、触发器及外部接口仍须在目标环境验证。
