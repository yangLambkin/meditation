# 04 - 业务流程

> 以文字时序图描述四个核心流程：打卡、实时排行榜、团队邀请、缓存恢复。逆向自 `meditationManager` / `teamManager` 云函数与其前端调用方（`pages/timer`、`pages/ranking`、`subpackages/team`、`miniprogram/utils/checkin.js`）。

---

## 1. 打卡流程（含统计更新）

```
[用户] → [timer 页面] 计时结束
  → cloudApi.recordMeditation({ duration, rating, experience })
    → meditationManager.recordMeditation
        ├─ 写入 meditation_records (date/timestamp/duration/rating/experience[])
        ├─ 更新 user_stats (db.command.inc):
        │     dailyTotalDuration += duration
        │     monthlyTotalDuration += duration
        │     totalDays / totalCount / totalDuration 累加
        │     重算 currentStreak / longestStreak / longestCheckInDays
        │     更新 lastCheckinDate / lastCheckinDuration / lastCheckin
        │     更新 monthlyStats['YYYY-MM']
        ├─ (遗留) updateRankings → 双写 rankings 集合 [日/月/总]
        └─ 返回 { recordId, date, timestamp }
  → [前端] 本地缓存更新 (meditation_checkin_<userId>)
  → 勋章评估: badgeManager 计算解锁 → cloudApi.updateUserBadges → 写回 user_stats.badges
```

要点：
- `dailyTotalDuration` 跨天重置；`monthlyTotalDuration` 跨月累加重置。
- `experience` 必须是 **数组**（遗留单字符串由 `updateMeditationRecord` 兼容）。

---

## 2. 实时排行榜流程

```
[用户] 打开排行榜页
  → cloudApi.getRankings({ period })
    → meditationManager.getRankings
        ├─ 查询 user_stats 按 dailyTotalDuration 降序 LIMIT 100
        ├─ 拼装 rankings: [{ openid, nickname, duration, rank }]
        ├─ 取当前用户:
        │     ├─ 命中前 100 → currentUserInTop100 = true, currentUserRank = 名次
        │     └─ 未命中 → 再查全量定位 currentUserRank, currentUserInTop100 = false
        └─ 返回 { type, period, snapshotTime, rankings, totalUsers,
                   currentUserOpenId, currentUserRank, currentUserInTop100 }

(后台, 每 6h)
  → meditationManager.config.json 定时器 `0 0 */6 * * * *`
    → generateRankingSnapshot({ type:'daily' })
        ├─ 取 user_stats 前 1000 名
        └─ 写入 ranking_snapshots { type, period, snapshotTime, rankings, totalUsers }
```

要点：
- `getRankings` **直接实时读 `user_stats`**，不读 `rankings` 集合（遗留）。
- 快照 `ranking_snapshots` 仅由定时器物化，用于历史/兜底。

## 3. 团队邀请流程

```
[创建者] createTeam 页面
  → cloudApi.createTeam({ teamName, teamIcon })
    → teamManager.createTeam → 写入 teams + team_members(创建者)
  → 生成邀请:
  → teamManager.generateInvite({ teamId, teamName, inviterName })
    → 写入 invites { inviteId, expireAt, status }

[分享] 邀请链接带 query: teamId / teamName / teamIcon / inviterName / inviteId

[受邀者] 打开 joinTeam 页面
  ├─ 已登录(openid 存在):
  │     → teamManager.joinTeam({ teamId, openid })
  │     → 写入 team_members + recordInviteRelation
  │     → 跳转 teamDetails
  └─ 未登录:
        → 跳转 pages/profile/profile
           带 fromPage=joinTeam & fromParams={teamId,inviteId,...}
        → 用户登录/补全档案 → profile 页回跳原流程
        → 重新执行 joinTeam
  → recordInviteAction({ inviteId, action:'accepted' })
  → 进入 teamDetails 查看成员打卡(getTeamMembersCheckinData / getMemberWeekCheckin)
```

要点：
- 未登录用户的重定向经由 `profile` 页的 `fromPage` / `fromParams` 机制，登录后回跳原邀请流（详见 `test_redirect_flow.js` 手动测试）。
- 邀请凭证有过期时间 `expireAt` 与 `status` 状态机。

## 4. 缓存恢复流程

```
[app.onLaunch]
  → setupCacheStatus()
       ├─ 首次启动 OR appVersion 变化
       │     → cacheStatus = 'initialized'
       │     → needsRecovery = true
       └─ 否则保持存储原值
  → checkinManager.strictCacheCheck()
       ├─ 读 cacheStatus / needsRecovery
       ├─ checkCriticalDataExists()      关键本地数据是否存在
       ├─ hasActualUserData()           是否已有真实用户数据
       └─ 命中恢复条件:
             → 从云端重建本地状态
             (getUserStats / getUserRecords / getUserBadges
              重新写入 meditation_checkin_<userId> 缓存)

[日常启动]
  → checkinManager.getUserId() 取本地 id
  → 读 wx.getStorageSync('userOpenId') 取 openid(若有)
  → 业务按"本地优先、云端兜底"运行
```

要点：
- `appVersion` 硬编码 `1.0.0`；需要"升级即迁移数据"时提升它。
- 身份以本地 ID 为主键，登录只替换 `userOpenId` 并写 `user_mappings`，不直接覆盖本地缓存键。

---

## 5. 身份迁移（登录）流程

```
[匿名态] localUserId = local_<ts>_<rand>, userOpenId = 同值
  → 用户触发微信登录
  → meditationManager.login({ code })
       → 换 openid
       → 建立 user_mappings { _openid, local_user_id }
       → 返回 openid
  → 前端存储 userOpenId = openid
  → cloudApi.migrateLocalData({ localUserId })
       → 将本地数据迁移到 openid 名下
       → 返回 { migrationStatus, migratedCount }
  → 本地缓存键 meditation_checkin_<localUserId> 仍可用(数据已续接)
```

要点：
- 不假设用户已登录；匿名态全功能可用，登录后平滑迁移。
- 默认昵称：未登录 `觉察者`，新建档案 `静心者`。
