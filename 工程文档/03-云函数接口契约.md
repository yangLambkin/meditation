# 云函数接口索引

云端入口以各目录的 `index.js` 为准；本文列出静坐核心调用与旧微信团队契约。身份取微信云函数上下文 OPENID，不能由客户端参数授予权限。业务结果通常为 `{ success, data?, error?, code? }`，必须检查 `success`。

## 1. `meditationManager`（event.type）

| 操作 | 输入与用途 |
| --- | --- |
| `login` | `{ code }`；返回平台身份 |
| `recordMeditation` | `{ data, localUserId }`；`data` 包含时长、原时间、体验、稳定身份及来源，幂等保存记录与统计 |
| `deleteMeditationRecord` | `{ data }`；按原记录身份删除，保留防重传凭证与必要同步待办 |
| `editMeditationRecord` | `{ data }`；校验原记录，事务更新内容、日期、统计及受影响历史日期的待办 |
| `getUserRecords` | `{ date }`；读取本人指定日期记录 |
| `getAllRecords` | `{}`；返回完整一致的本人记录数组；读写并发无法取得完整快照时失败，不返回伪完整分页 |
| `getUserStats` / `getMonthlyStats` | `{}` / `{ month }`；本人统计与按月统计 |
| `updateMeditationRecord` | `{ recordId, experience }`；历史体验更新入口，保留单字符串兼容 |
| `saveExperienceRecord` / `deleteExperienceRecord` | `{ record, localUserId }` / `{ recordId }`；独立体验的保存和删除 |
| `migrateLocalData` / `getUserMapping` | `{ localUserId }` / `{}`；旧本地身份映射 |
| `updateUserProfile` | `{ userInfo, userType }`；已有资料只更新允许且明确提供的字段，省略字段不覆盖 |
| `getUserProfile` / `migrateUserProfile` | `{}` / `{ oldUserInfo }`；资料查询与旧资料迁移 |
| `getRankingSnapshot` | `{ rankingType }`；保留的实时排名兼容接口，不生成定时快照 |
| `updateUserBadges` / `getUserBadges` | `{ badges }` / `{}`；勋章合并与读取 |

前端调用和准确请求字段见 `miniprogram/utils/cloudApi.js`；身份、幂等、修改和删除行为由 `tests/recordIdempotencyCloud.test.js`、`tests/editMeditationCloud.test.js`、`tests/deleteMeditationCloud.test.js` 等覆盖。新增记录先成功落本机，再异步上传；具体补传规则见 [自动恢复](../docs/2026-10-10-auto-sync-recovery.md)。

反馈操作 `submitFeedback/getMyFeedback/getFeedbackAlert/markFeedbackRead` 见 [反馈说明](../docs/2026-09-29-feedback.md)。补录操作 `submitBackfillRequest/getMyBackfillRequests/getBackfillAlert/markBackfillRead` 见 [补录说明](../docs/2026-10-05-backfill.md)。

`recomputeUserBadges` 和 `migrateBusinessDates` 是受保护运维接口，需指定身份、环境和目标；参数与写入门槛见 [运维说明](../docs/maintenance-access.md)。旧 `getRankings/generateRankingSnapshot/initRankingSnapshot` 不再是可调用入口。

## 2. 旧微信团队：`teamManager`（event.type）

此接口仅维护已有微信团队。新建团队与 `bijing_` 前缀团队通过 `teamGateway.js` 调用 data OpenAPI，见 [团队接入说明](../docs/team-openapi.md)。

### 2.1 `createTeam`
- 输入：`{ name, description?, icon?, creatorName?, practiceStartDate?, dailyGoalMinutes? }`。
- 输出：`{ success, data: { teamId, team } }`；允许同一账号创建多个团队，活跃团队名称唯一。
- 可选练习设置：新建省略或传 `null` 均保存为 `null`。设置日期须为不晚于当前练习日的 `YYYY-MM-DD`，分钟须为 1–1440 的整数。

### 2.2 `getUserTeams`
- 输入：`{}`，返回当前云端身份创建或加入的团队。
- 输出：`{ success, data: [teams] }`

### 2.3 `deleteTeam`
- 输入：`{ teamId }`
- 输出：`{ success }`

### 2.4 `joinTeam`
- 输入：`{ teamId, inviteId }`；调用格式为 `{ type: 'joinTeam', data: { teamId, inviteId } }`。
- 输出：`{ success, data: { teamId } }`。
- 权限与校验：加入者身份只取微信云函数上下文 `OPENID`，不信任客户端 `openid` / `inviterId`。新成员必须提供属于该团队、签发人仍为当前团长或副团长且未过期的邀请；有效状态为 `pending` 或 `accepted`。邀请有效期 7 天，可供多人加入使用，团队最多 50 人。
- 写入：事务更新 `teams.members` / `memberCount`，并写入 `team_members` 中由邀请凭证确认的 `invitedBy` / `inviteId`。已在团队的用户重复调用直接成功，不重复增加人数。
- 兼容：普通成员以前生成的邀请、没有 `inviteId` 的旧分享均不能用于新成员加入；需联系负责人重新生成邀请。

### 2.5 `leaveTeam`
- 输入：`{ teamId, openid }`
- 输出：`{ success }`

### 2.6 `updateTeam`
- 输入：`{ teamId, teamData: { name?, description?, icon?, practiceStartDate?, dailyGoalMinutes? } }`。
- 输出：`{ success, data: { teamId } }`。仅创建者可编辑；省略字段保持原值，练习设置传 `null` 可清空。名称/介绍最长 20/100 字符；身份、成员及活跃状态不接受客户端修改。

### 2.7 `getTeamInfo`
- 输入：`{ teamId }`
- 输出：`{ success, data: team }`
- `members` 为成员资料列表，含 `nickname`、`avatarUrl`、`isCreator`、`isDeputy`、`role`；仅同团队成员可见 `openid` 和团队的 `deputyLeaders` 数组，`isMember` 由云端身份判定。副团长任免与团长交接见 [团队角色说明](../docs/2026-09-29-team-roles.md)。
- 此接口及团队列表返回标准化练习设置：`practiceStartDate`、`dailyGoalMinutes` 可为 `null`；`effectivePracticeStartDate` 为实际统计起点，`hasPracticeStartDate` 表示是否保存了有效起始日期，`dayBoundaryHour` 固定为 2。明确为 `null` 的日期回退到创建所属练习日用于统计；历史缺字段团队沿用创建日/20 分钟，已有有效值不变。

### 2.8 `getTeamMembersCheckinData`
- 输入：`{ teamId }`
- 输出：`{ success, data }`

### 2.9 `generateInvite`
- 输入：`{ teamId, inviterName? }`；调用格式为 `{ type: 'generateInvite', data: { teamId, inviterName } }`。
- 输出：`{ success, data: { inviteId, sharePath, expireTime, title } }`，`expireTime` 为毫秒时间戳。
- 权限：当前团长或副团长可生成邀请（身份来自微信云函数上下文，副团长须在当前 `deputyLeaders` 及成员名单中），普通成员与非成员均被拒绝。团队名称以云端数据为准。
- 写入：创建 `invites` 凭证，状态为 `pending`、有效期为 7 天。返回的 `sharePath` 指向加入页并包含 `teamId` / `teamName` / `inviterId` / `inviteId`；凭证可供多人使用，加入时仍须重新校验签发人当前权限、状态与有效期。
- 前端：团长或副团长在详情页显式点击「邀请」准备凭证，成功后才显示「分享邀请」并开放好友分享；普通成员不显示邀请入口。

### 2.10 `recordInviteAction`
- 输入：`{ teamId, inviteId }`；调用格式为 `{ type: 'recordInviteAction', data: { teamId, inviteId } }`。
- 输出：`{ success, data: { actionId } }`。
- 权限与写入：当前团长或副团长可记录邀请，凭证必须属于该团队且由本人生成；写入 `invite_actions`，`actionType` 固定为 `generate`，不接受客户端指定邀请人或动作类型。
- 该接口仅记录邀请生成行为，不授予加入资格，也不是受邀者加入后必须调用的步骤。

### 2.11 `recordInviteRelation`
- 输入：`{ inviteId, openid }`
- 输出：`{ success }`

### 2.12 `getMemberWeekCheckin`
- 输入：`{ teamId, openid? }`
- 输出：`{ success, data }`

### 2.13 `getAllTeams`
- 输入：`{}`
- 输出：`{ success, data: { teams, count } }`，团队公共资料含标准化练习设置，不含成员身份列表。

### 2.14 `getTeamPracticeReport`
- 输入：`{ teamId, month? }`；仅当前活跃团队成员可调用，不接受客户端扩展成员查询范围。历史统计主页面省略 `month`，展示起始日期至昨日的全部历史；接口仍支持可选的 `YYYY-MM` 月份参数。
- 输出：`{ success, data: { teamId, creator, deputyLeaders, businessDate, nextResetAt, settings, history, summary, members, overview } }`。`creator`、`deputyLeaders` 供页面校验最新角色；`nextResetAt` 为毫秒时间戳，练习日固定北京时间 02:00 切换。
- `settings` 同 2.7；`history: { startDate, endDate, totalDays }` 从有效起点至昨日。全体当前成员采用同一区间，不按加入时间截断；修改规则后重新计算。仅累计有效日期、非未来时间、正时长记录，旧记录缺有效时间戳时沿用 `date`，不返回日记等原始内容。
- `summary: { memberCount, notPracticedCount, practicedCount, belowGoalCount, qualifiedCount }`；`practicedCount` 是今日有练习总人数。有目标时 `todayStatus` 为 `not_practiced` / `below_goal` / `qualified`，无目标时为 `not_practiced` / `practiced`，达标和不足人数均为 0。
- `members` 含 `openid`、`nickname`、`avatarUrl`、`isCreator`、`todayMinutes`、`todayStatus`；历史字段为 `practiceDays`、`qualifiedDays`、`belowGoalDays`、`missedDays`、`unmetDays`、`totalMinutes`，均不含今日。无目标时保留实际练习天数、分钟和未练习天数，`qualifiedDays` / `belowGoalDays` / `unmetDays` 为 0。
- 成员新增字段：`totalPracticeCount`、`cumulativeMinutes` 从有效起点累计至今日；`todayPracticeCount` 为今日次数；`lastPracticeDate` 为最近练习业务日，`lastPracticeAt` 为该日已知的最近毫秒时间戳。无记录时两个最近练习字段为 `null`、次数和分钟为 0；最近日期只有旧版日期记录时，时间戳为 `null`，不展示更早日期的时间。
- 传入 `month` 时，`history` 增加 `month`、`minMonth`（有效起点所在月）、`maxMonth`（当前练习日所在月），历史范围取所选月与有效起点至昨日的交集；合法但越界的月份夹到边界，无效格式拒绝。月初可返回 `totalDays: 0`。只有历史天数和历史分钟随月份变化，今日与上述累计字段、`overview` 保持原统计范围。
- `overview: { memberCount, totalPracticeCount, activeMemberCount, activityRate }`；次数为上述成员累计次数之和，活跃人数为今日练习人数，活跃度为四舍五入的 0–100 整数百分比。
- 前端「团队成员」展示成员累计数据，「查看记录」分为今日练习与历史统计；团长可编辑完整团队资料，其他成员只读规则。

### 2.15 `getTeamMemberPracticeRecords`
- 输入：`{ teamId, memberOpenid }`；查看者身份来自云函数上下文，查看者和目标成员都必须属于当前活跃团队。
- 输出：`{ success, data: { member, startDate, businessDate, records } }`；`member` 包含 `openid`、`nickname`、`avatarUrl`、`isCreator`。
- `records` 包含 `{ _id, date, timestamp, duration, source? }`，按日期和时间倒序。`date` 为北京时间 02:00 划分的练习日，`timestamp` 为毫秒时间戳或旧版无时间记录的 `null`，`duration` 为正数分钟。不返回感受、日记及体验内容。
- 日期与时长筛选沿用团队报告：从有效统计起点 `startDate` 至当前时刻，排除未来时间和无效时长；按 `_id` 游标完整读取，不受单页 100 条限制。
- 前端复用月记录与日记录页面，以 `teamId`、`memberOpenid` 保留成员上下文，成员模式只读且不使用个人记录缓存。缺少成员参数、权限或网络失败时展示错误并支持重试。

### 2.16 `getTeamHistoryDetails`
- 输入：`{ teamId, month?, filter?, memberOpenid?, cursor?, limit? }`；仅当前活跃团队成员可调用，指定的 `memberOpenid` 也必须是当前成员。月份规则与 2.14 相同，明细页面每次请求均携带所选 `month`；从历史汇总进入时默认当前练习日所属月份，之后可切换月份。
- `filter` 默认为 `unmet`，支持 `unmet`（未练习或时长不足）、`not_practiced`、`below_goal`、`all`。无目标时 `unmet` / `below_goal` 归一为 `not_practiced`，响应返回实际使用的筛选项。
- `limit` 默认为 50，取 1–100 的整数。首屏省略 `cursor` 或传 `null`，后续原样使用响应 `nextCursor: { date, memberOpenid }`；`nextCursor` 为 `null` 表示结束。
- 输出：`{ success, data: { teamId, businessDate, settings, history, filter, items, nextCursor } }`。`settings` 和 `history` 与团队练习报告一致，仅统计有效起点至昨日，不包含当前练习日。
- `items` 每项为 `{ date, openid, nickname, avatarUrl, isCreator, minutes, status }`，按日期倒序、同日成员 openid 升序。`minutes` 是该成员当日累计有效分钟，`status` 为 `not_practiced` / `below_goal` / `qualified` / `practiced`；无练习记录也会生成 0 分钟的未练习项。一天多次练习合并成一项，不返回日记和感受。
- 统计沿用报告的北京时间 02:00 分日、有效记录筛选、补偿求和及浮点达标判断。前端进入日记录时继续携带成员身份和日期；加载后续页发现统计区间或目标变化时，从首屏重新加载。
- 月份切换时丢弃旧明细和游标，保留成员及状态筛选；后续分页始终携带同一个月份，游标日期必须落在该月实际统计范围内，不跨月追加。
