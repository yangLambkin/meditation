# 03 - 云函数接口契约

> 逆向自 `cloudfunctions/meditationManager/index.js` 与 `cloudfunctions/teamManager/index.js`。冥想接口经 `miniprogram/utils/cloudApi.js` 调用；团队接口由团队页面及 `utils/teamManager.js` 调用。
>
> 统一信封：`{ success: boolean, data?: any, error?: string }`（个别接口额外返回 `message`）。
> 两者均用 `event.type` 分发；团队接口调用格式为 `{ type: 操作名, data: 输入字段 }`，身份只取微信云函数上下文 `OPENID`。

## 2. `teamManager`（event.type）

### 2.1 `createTeam`
- 输入：`{ name, description?, icon?, creatorName?, practiceStartDate?, dailyGoalMinutes? }`。
- 输出：`{ success, data: { teamId, team } }`；允许同一账号创建多个团队，活跃团队名称唯一。
- 可选练习设置：新建省略或传 `null` 均保存为 `null`。设置日期须为不晚于当前练习日的 `YYYY-MM-DD`，分钟须为 1–1440 的整数。

### 2.2 `getUserTeams`
- 输入：`{}`，返回当前云端身份创建或加入的团队。
- 输出：`{ success, data: [teams] }`

### 2.3 `deleteTeam`
- 输入：`{ teamId }`
- 输出：`{ success }`

### 2.4 `joinTeam`
- 输入：`{ teamId, inviteId }`；调用格式为 `{ type: 'joinTeam', data: { teamId, inviteId } }`。
- 输出：`{ success, data: { teamId } }`。
- 权限与校验：加入者身份只取微信云函数上下文 `OPENID`，不信任客户端 `openid` / `inviterId`。新成员必须提供属于该团队、由当前负责人（`team.creator`）生成且未过期的邀请；有效状态为 `pending` 或 `accepted`。邀请有效期 7 天，可供多人加入使用，团队最多 50 人。
- 写入：事务更新 `teams.members` / `memberCount`，并写入 `team_members` 中由邀请凭证确认的 `invitedBy` / `inviteId`。已在团队的用户重复调用直接成功，不重复增加人数。
- 兼容：普通成员以前生成的邀请、没有 `inviteId` 的旧分享均不能用于新成员加入；需联系负责人重新生成邀请。

### 2.5 `leaveTeam`
- 输入：`{ teamId, openid }`
- 输出：`{ success }`

### 2.6 `updateTeam`
- 输入：`{ teamId, teamData: { name?, description?, icon?, practiceStartDate?, dailyGoalMinutes? } }`。
- 输出：`{ success, data: { teamId } }`。仅创建者可编辑；省略字段保持原值，练习设置传 `null` 可清空。名称/介绍最长 20/100 字符；身份、成员及活跃状态不接受客户端修改。

### 2.7 `getTeamInfo`
- 输入：`{ teamId }`
- 输出：`{ success, data: team }`
- `members` 为成员资料列表，含 `nickname`、`avatarUrl`、`isCreator`；仅同团队成员可见 `openid`，`isMember` 由云端身份判定。
- 此接口及团队列表返回标准化练习设置：`practiceStartDate`、`dailyGoalMinutes` 可为 `null`；`effectivePracticeStartDate` 为实际统计起点，`hasPracticeStartDate` 表示是否保存了有效起始日期，`dayBoundaryHour` 固定为 4。明确为 `null` 的日期回退到创建所属练习日用于统计；历史缺字段团队沿用创建日/20 分钟，已有有效值不变。

### 2.8 `getTeamMembersCheckinData`
- 输入：`{ teamId }`
- 输出：`{ success, data }`

### 2.9 `generateInvite`
- 输入：`{ teamId, inviterName? }`；调用格式为 `{ type: 'generateInvite', data: { teamId, inviterName } }`。
- 输出：`{ success, data: { inviteId, sharePath, expireTime, title } }`，`expireTime` 为毫秒时间戳。
- 权限：仅当前负责人（微信云函数上下文 `OPENID === team.creator`）可生成邀请，普通成员与非成员均被拒绝。团队名称以云端数据为准。
- 写入：创建 `invites` 凭证，状态为 `pending`、有效期为 7 天。返回的 `sharePath` 指向加入页并包含 `teamId` / `teamName` / `inviterId` / `inviteId`；凭证可供多人使用，加入时仍须重新校验负责人身份、状态与有效期。
- 前端：负责人在详情页显式点击「邀请」准备凭证，成功后才显示「分享邀请」并开放好友分享；普通成员不显示邀请入口。

### 2.10 `recordInviteAction`
- 输入：`{ teamId, inviteId }`；调用格式为 `{ type: 'recordInviteAction', data: { teamId, inviteId } }`。
- 输出：`{ success, data: { actionId } }`。
- 权限与写入：仅当前负责人可记录邀请，凭证必须属于该团队且由本人生成；写入 `invite_actions`，`actionType` 固定为 `generate`，不接受客户端指定邀请人或动作类型。
- 该接口仅记录邀请生成行为，不授予加入资格，也不是受邀者加入后必须调用的步骤。

### 2.11 `recordInviteRelation`
- 输入：`{ inviteId, openid }`
- 输出：`{ success }`

### 2.12 `getMemberWeekCheckin`
- 输入：`{ teamId, openid? }`
- 输出：`{ success, data }`

### 2.13 `getAllTeams`
- 输入：`{}`
- 输出：`{ success, data: { teams, count } }`，团队公共资料含标准化练习设置，不含成员身份列表。

### 2.14 `getTeamPracticeReport`
- 输入：`{ teamId }`；仅当前活跃团队成员可调用，不接受客户端扩展成员查询范围。
- 输出：`{ success, data: { teamId, businessDate, nextResetAt, settings, history, summary, members, overview } }`。`nextResetAt` 为毫秒时间戳，练习日固定北京时间 04:00 切换。
- `settings` 同 2.7；`history: { startDate, endDate, totalDays }` 从有效起点至昨日。全体当前成员采用同一区间，不按加入时间截断；修改规则后重新计算。仅累计有效日期、非未来时间、正时长记录，旧记录缺有效时间戳时沿用 `date`，不返回日记等原始内容。
- `summary: { memberCount, notPracticedCount, practicedCount, belowGoalCount, qualifiedCount }`；`practicedCount` 是今日有练习总人数。有目标时 `todayStatus` 为 `not_practiced` / `below_goal` / `qualified`，无目标时为 `not_practiced` / `practiced`，达标和不足人数均为 0。
- `members` 含 `openid`、`nickname`、`avatarUrl`、`isCreator`、`todayMinutes`、`todayStatus`；历史字段为 `practiceDays`、`qualifiedDays`、`belowGoalDays`、`missedDays`、`unmetDays`、`totalMinutes`，均不含今日。无目标时保留实际练习天数、分钟和未练习天数，`qualifiedDays` / `belowGoalDays` / `unmetDays` 为 0。
- 成员新增字段：`totalPracticeCount`、`cumulativeMinutes` 从有效起点累计至今日；`todayPracticeCount` 为今日次数；`lastPracticeDate` 为最近练习业务日，`lastPracticeAt` 为该日已知的最近毫秒时间戳。无记录时两个最近练习字段为 `null`、次数和分钟为 0；最近日期只有旧版日期记录时，时间戳为 `null`，不展示更早日期的时间。
- `overview: { memberCount, totalPracticeCount, activeMemberCount, activityRate }`；次数为上述成员累计次数之和，活跃人数为今日练习人数，活跃度为四舍五入的 0–100 整数百分比。
- 前端「团队成员」展示成员累计数据，「查看记录」分为今日练习与历史统计；团长可编辑完整团队资料，其他成员只读规则。

### 2.15 `getTeamMemberPracticeRecords`
- 输入：`{ teamId, memberOpenid }`；查看者身份来自云函数上下文，查看者和目标成员都必须属于当前活跃团队。
- 输出：`{ success, data: { member, startDate, businessDate, records } }`；`member` 包含 `openid`、`nickname`、`avatarUrl`、`isCreator`。
- `records` 包含 `{ _id, date, timestamp, duration, source? }`，按日期和时间倒序。`date` 为北京时间 04:00 划分的练习日，`timestamp` 为毫秒时间戳或旧版无时间记录的 `null`，`duration` 为正数分钟。不返回感受、日记及体验内容。
- 日期与时长筛选沿用团队报告：从有效统计起点 `startDate` 至当前时刻，排除未来时间和无效时长；按 `_id` 游标完整读取，不受单页 100 条限制。
- 前端复用月记录与日记录页面，以 `teamId`、`memberOpenid` 保留成员上下文，成员模式只读且不使用个人记录缓存。缺少成员参数、权限或网络失败时展示错误并支持重试。

## 4. 前端调用封装（cloudApi.js）

所有对 `meditationManager` 的调用都应经 `miniprogram/utils/cloudApi.js` 的 `callFunction` 封装（统一处理信封、`showError`、loading）。新增后端能力时：
1. 在 `meditationManager/index.js` 加 `case` + handler；
2. 在 `cloudApi.js` 加对应的前端方法；
3. 页面只调用 `cloudApi.xxx()`，不直接 `wx.cloud.callFunction`。
