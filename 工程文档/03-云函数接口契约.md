# 03 - 云函数接口契约

> 逆向自 `cloudfunctions/meditationManager/index.js` 与 `cloudfunctions/teamManager/index.js`。前端统一经 `miniprogram/utils/cloudApi.js` 调用。
>
> 统一信封：`{ success: boolean, data?: any, error?: string }`（个别接口额外返回 `message`）。
> 注意字段名差异：`meditationManager` 用 `event.type` 分发；`teamManager` 用 `event.action` 分发。

---

## 1. `meditationManager`（event.type）

### 1.1 `login`
- 输入：`{ code }`
- 输出：`{ success, openid, message }`
- 说明：用 `code` 换 openid，并完成本地 ID 到 openid 的映射。

### 1.2 `recordMeditation`
- 输入：`{ data: { duration, rating, experience }, localUserId }`
- 输出：`{ success, data: { recordId, date, timestamp } }`
- 说明：写入 `meditation_records`，并联动更新 `user_stats`（连续天数、时长累加 `db.command.inc`）、双写 `rankings`（遗留）。

### 1.3 `getUserRecords`
- 输入：`{ date }`
- 输出：`{ success, data: [meditation_records...] }`

### 1.4 `getUserStats`
- 输入：`{}`
- 输出：`{ success, data: { ...user_stats 全字段 } }`

### 1.5 `getRankings`
- 输入：`{ period }`
- 输出：`{ success, data: { type, period, snapshotTime, rankings, totalUsers, currentUserOpenId, currentUserRank, currentUserInTop100 } }`
- 说明：实时查 `user_stats` 按 `dailyTotalDuration` 降序 `limit(100)`；当前用户不在前 100 时再查全量定位真实排名。

### 1.6 `getMonthlyStats`
- 输入：`{ month }`
- 输出：`{ success, data: { month, dailyStats, totalCount, totalDuration } }`

### 1.7 `getAllRecords`
- 输入：`{}`
- 输出：`{ success, data: [全部 meditation_records] }`

### 1.8 `updateMeditationRecord`
- 输入：`{ recordId, experience }`
- 输出：`{ success, data: { recordId, date, experience } }`
- 说明：处理 `experience` 单字符串的遗留兼容，新代码一律写数组。

### 1.9 `saveExperienceRecord`
- 输入：`{ record: { text, uniqueId }, localUserId }`
- 输出：`{ success, data: { recordId, timestamp } }`
- 说明：写入独立 `experience_records`。

### 1.10 `deleteExperienceRecord`
- 输入：`{ recordId }`
- 输出：`{ success, data: { deletedRecordId } }`

### 1.11 `migrateLocalData`
- 输入：`{ localUserId }`
- 输出：`{ success, data: { openid, localUserId, migrationStatus, migratedCount, message } }`
- 说明：将本地 ID 数据迁移到 openid 名下，建立 `user_mappings`。

### 1.12 `getUserMapping`
- 输入：`{}`
- 输出：`{ success, data: [user_mappings...] }`

### 1.13 `updateUserProfile`
- 输入：`{ userInfo, userType }`
- 输出：`{ success, data: { openid, updateTime, userType } }`

### 1.14 `getUserProfile`
- 输入：`{}`
- 输出：`{ success, data: userProfile | null }`

### 1.15 `migrateUserProfile`
- 输入：`{ oldUserInfo }`
- 输出：`{ success, data: { openid, migrationTime, migratedFrom } }`

### 1.16 `getRankingSnapshot`
- 输入：`{ rankingType }`
- 输出：`{ success, data: rankingData }`

### 1.17 `generateRankingSnapshot`（定时器触发）
- 输入：`{ type }`（或由 `event.Type === 'timer'` 触发，无参默认 daily）
- 输出：`{ success, data: snapshot }`
- 说明：`meditationManager/config.json` 配置定时器 `0 0 */6 * * * *` 每 6h 调用。

### 1.18 `initRankingSnapshot`
- 输入：`{}`
- 输出：`{ success, data: { snapshotId, testData } }`

### 1.19 `updateUserBadges`
- 输入：`{ badges }`
- 输出：`{ success, data: { updatedBadges } }`
- 说明：把勋章状态写回 `user_stats.badges`。

### 1.20 `getUserBadges`
- 输入：`{}`
- 输出：`{ success, data: badges }`

## 3. 其他云函数

| 云函数 | 调用方式 | 输入 / 输出 | 说明 |
| --- | --- | --- | --- |
| `autoCreateCollections` | 一次性手动触发 | — | 创建集合 + 样例数据；**默认不在 `app.js` 调用**（被注释） |
| `cleanupTestData` | `cli cloud function invoke` 或 npm 脚本 | `{ mode: 'stats'|'safe'|'full' }` | 测试数据清理，见 `06-部署与运维.md` |
| `getRandomWisdom` | `wx.cloud.callFunction` | 输出随机 `wisdom_quotes` 一行 | 每日智慧语 |

## 4. 前端调用封装（cloudApi.js）

所有对 `meditationManager` 的调用都应经 `miniprogram/utils/cloudApi.js` 的 `callFunction` 封装（统一处理信封、`showError`、loading）。新增后端能力时：
1. 在 `meditationManager/index.js` 加 `case` + handler；
2. 在 `cloudApi.js` 加对应的前端方法；
3. 页面只调用 `cloudApi.xxx()`，不直接 `wx.cloud.callFunction`。
