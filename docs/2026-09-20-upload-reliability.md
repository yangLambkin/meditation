# 2026-09-20 静坐上传可靠性修复

本补丁修复“首页已有本地记录，但云端保存失败且没有重试”的问题。只在首页提供统一上传入口；旧本机记录也在全部日期的预览清单中，用户确认后补传，不运行后台迁移或清理。

## 新行为

- `meditationManager` 明确检测到 `meditation_locks` 集合缺失时，仅创建这个空辅助集合，再重新读取锁并保存记录。并发创建可安全重试，记录、统计和版本号仍在同一事务中提交。
- 权限、网络和其他请求失败不会被当成“集合不存在”或“保存成功”。无法创建锁集合时返回 `LOCK_COLLECTION_UNAVAILABLE`；云端失败后记录保留在本机并显示待上传状态。
- 新记录先安全写入本机，再在后台尝试一次上传。首页“记录静坐”保存本机成功后立即关闭弹窗并刷新记录，提示“已保存”；记录页提示“已保存到本机”并返回首页，计时完成页同样不等待云端。首页列表在请求期间显示“正在上传”，不计入待上传数量；云端确认后更新为已上传，5 秒无结果则标记超时并提供手动上传。上传失败始终保留本机记录，后台上传结果只更新列表状态，不再弹出提示或打断下一次操作。
- 待上传记录全部由首页“重试上传”按钮统一处理，涵盖所有日期的新版待上传及旧版未确认记录，复用原始时间、日期、时长和稳定身份。旧记录只有在用户确认预览后才持久化上传身份和账号，再与本次预览中的新版待上传记录一起进入队列。
- `syncWithCloud` 默认只读取完整云端记录校准本机；只有显式 `uploadPending: true` 才补传，且不追加云端读取等待。云端确认 `recordId` 后才标记已上传，重试不会重复累计统计。刷新首页及重建缓存会保留正在上传及待上传状态。
- 首页继续在同一列表显示已上传、正在上传与待上传记录。旧无云端身份的记录显示“本机记录，未确认上传”，并计入首页统一提醒；点击顶部“重试上传”展示全部日期记录的日期、时间、时长、心情和体验。单条记录和“全部”页不再提供上传按钮。明确属于其他账号的缓存记录不出现在当前账号的首页，但保留原存储。
- 旧记录补传先持久化固定身份和账号，原时间、时长及手动补录日期保持不变。云端通过 `recoverLegacy` 在事务内核对同账号、业务日期、精确时间和时长：唯一匹配无稳定身份的旧云端记录时返回原 ID，不重复统计；存在多个候选则拒绝上传。早期版本由云端生成保存时间，因此未精确匹配但同日同一时长存在无身份旧记录，或精确匹配了另一稳定身份时，也保留本机并提示核对。后续重试及缓存重建保留这一核对方式，未出现在本次预览中的记录不连带补传。
- 同步必经不会补传本机记录；所选日期仍有正在上传或待上传记录时阻止提交，避免同步不完整的时长。正在上传时提示等待，待上传时提示到首页手动上传。其他日期的未上传记录不阻断所选日期。
- 待上传记录绑定首次使用的微信账号，云端同时校验 `expectedOpenid`。切换账号不会把这些记录上传给另一个账号。
- 手动补录首次上传仍受最近三个业务日的限制；过期失败保留本地记录与错误提示。已经成功上传的同身份重试返回原结果。
- 维护接口的 `dryRun` 保持只读，不创建 `meditation_locks`。
- `getAllRecords` 在整轮分页前后读取用户写入版本；分页期间发生事务增删时重新读取全部页，连续三轮变化则返回 `RETRY_REQUIRED`，不把遗漏记录的结果作为完整快照返回。旧环境缺少锁集合时仍可只读查询，不触发建表。

分页一致性保护覆盖会推进用户版本的静坐事务写入。直接在数据库控制台或其他未更新版本号的运维脚本中改数据，不在这项并发保护范围内；完成运维操作后需重新刷新。这项保护不执行历史数据迁移或清理。

## 首次上传和手动补传流程

1. 登录后的新记录在本机保存后异步尝试一次上传，五秒期限涵盖上传链路。上传中不会先显示“待上传”；首页、记录页和计时完成页仅在校验感受和保存本机期间锁定提交控件并防止重复点击，保存后即可完成操作，不等待上传结果。本机保存失败时保留表单，允许以同一记录身份重试。
2. 网络恢复、冷启动、从后台返回、进入首页、登录和下拉刷新均只读取云端，不补传本机待上传记录。
3. 首页“重试上传”先展示当前账号全部日期的待上传清单（包含旧版未确认记录），按日期列出时间、时长、心情及体验，并单独说明已明确无法上传或数据不完整的记录。确认后只尝试本次预览中的可重试记录，取消不上传，预览后新产生的待上传记录留待下次操作；账号切换后需重新查看清单。一次操作共用五秒期限，并发点击复用同一请求。失败、超时后等待下一次手动操作，不启动重试定时器。
4. 新增另一条记录只尝试上传该新记录，不顺带上传此前失败的记录。重复提交同一个已保存身份也不会隐式补传。
5. 小程序重启后，已中断的“正在上传”状态恢复为待上传，等待用户操作。后台结束的计时先同步保存本机及清除完成草稿，只保留计时结束及本机保存提示，上传结果不再更新提示，也不会在返回计时页时补弹上传结果。

小程序被关闭或系统挂起时，不假定定时器继续运行。游客记录在登录后也必须手动上传。手动补录若首次成功上传时已超出原有三天窗口，会保留本机并明确显示超期。

首页“待上传或待确认”数量与预览覆盖所有日期，不受“最近三天记录”列表的显示范围限制。新版依据上传标记和账号归属识别待上传记录；旧版没有云端 ID 的记录以未确认状态进入预览，确认时由云端核对。“全部”月度页仅查看记录，不提供上传入口；更早的记录统一从首页补传。

## 部署顺序

1. 先上传并部署 **`meditationManager`**，在云端安装依赖。必须先具备集合自愈、稳定身份去重、旧记录补传核对及账号校验，再让新版客户端发送重试请求。
2. 在测试环境验证一条新打卡的云端记录和统计，并验证网络失败后恢复不会自动上传、手动上传只保存一条。集合缺失场景应在隔离的测试环境检查，不删除线上锁集合来模拟。
3. 再上传、审核并发布包含待上传状态和重试队列的**小程序**。

无需先手动创建锁集合，也无需调用会检查所有集合的 `autoCreateCollections`。如果目标环境不允许云函数创建集合，可由管理员仅创建空的 `meditation_locks`，权限设为仅云函数/管理员可读写；不要为解决上传失败放宽客户端权限。恢复后新版待上传记录可重试。

本次只修改代码并做本地验证，尚未部署云函数或发布小程序。
