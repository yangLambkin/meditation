# 2026-09-20 静坐上传可靠性修复

本补丁修复“首页已有本地记录，但云端保存失败且没有重试”的问题。9 月 22 日补传规则更新为：打开或返回小程序时自动补传当天的明确待上传记录；更早日期及旧版未确认记录由首页统一入口手动确认。当天沿用全应用北京时间 02:00 换日规则，补录按用户所选业务日期判断，不运行后台迁移或清理。

## 新行为

- 记录静坐、正计时、倒计时的首次上传，以及当天自动补传、首页手动补传，都复用 `checkin.asyncBackupToCloud → backupRecordToCloud → cloudApi.recordMeditation`。入口只负责保存新记录或选择待上传名单；网络检查、内容审核、每次三秒超时、100ms 间隔和最多三次重试、稳定身份去重、云端确认及本机状态更新只有一套实现。补传读取已存本机的原始时间、业务日期、时长和体验，不重新创建记录。
- `meditationManager` 明确检测到 `meditation_locks` 集合缺失时，仅创建这个空辅助集合，再重新读取锁并保存记录。并发创建可安全重试，记录、统计和版本号仍在同一事务中提交。
- 权限、网络和其他请求失败不会被当成“集合不存在”或“保存成功”。无法创建锁集合时返回 `LOCK_COLLECTION_UNAVAILABLE`；云端失败后记录保留在本机并显示待上传状态。
- 新记录先安全写入本机；确认在线后再在后台上传。离线或网络探测失败时不发送云端写入请求，保留本机待上传。网络持续可用时，可重试的失败每次等待 100ms，最多额外重试三次（含首次共四次），当天自动补传和手动补传均复用此重试机制。首页“记录静坐”保存本机成功后立即关闭弹窗并刷新记录，提示“已保存”；记录页提示“已保存到本机”并返回首页，计时完成页同样不等待云端。首页列表在请求期间显示“正在上传”，不计入待上传数量；云端确认后更新为已上传，每次上传尝试独立限时 3 秒（包括网络探测、文本检测和写入），云请求超时后也按 100ms 间隔重试，四次均超时约 12.3 秒后标记失败并提供手动上传。上传失败始终保留本机记录，后台上传结果只更新列表状态，不再弹出提示或打断下一次操作。
- 一轮上传及同批补传共用断网版本；一旦检测到断网或网络探测失败，该轮即失效。即使在 100ms 重试等待或文本检测期间迅速恢复网络，也不会继续发送该轮的后续写入、重试或上传下一条记录；当天记录可在下次打开小程序时自动开始新一轮，也可手动重试。已发送并被云端接受的请求无法撤回，其真实保存结果仍会正常核对。
- 打开或返回小程序时，`retryTodayBackups` 只选当前账号当天的新版待上传记录，跳过正在上传、已忽略、已阻止上传及正在删除的记录。首页“重试上传”按钮仍涵盖所有日期的新版待上传及旧版未确认记录，复用原始时间、日期、时长和稳定身份。旧记录只有在用户确认预览后才持久化上传身份和账号，再与本次预览中的新版待上传记录一起进入队列。
- `syncWithCloud` 默认只读取完整云端记录校准本机；只有显式 `uploadPending: true` 才补传，且不追加云端读取等待。云端确认 `recordId` 后才标记已上传，重试不会重复累计统计。刷新首页及重建缓存会保留正在上传及待上传状态。
- 首页继续在同一列表显示已上传、正在上传与待上传记录。旧无云端身份的记录显示“本机记录，未确认上传”，并计入首页统一提醒；点击顶部“重试上传”展示全部日期记录的日期、时间、时长、心情和体验。单条记录和“全部”页不再提供上传按钮。明确属于其他账号的缓存记录不出现在当前账号的首页，但保留原存储。
- 旧记录补传先持久化固定身份和账号，原时间、时长及手动补录日期保持不变。云端通过 `recoverLegacy` 在事务内核对同账号、业务日期、精确时间和时长：唯一匹配无稳定身份的旧云端记录时返回原 ID，不重复统计；存在多个候选则拒绝上传。早期版本由云端生成保存时间，因此未精确匹配但同日同一时长存在无身份旧记录，或精确匹配了另一稳定身份时，也保留本机并提示核对。后续重试及缓存重建保留这一核对方式，未出现在本次预览中的记录不连带补传。
- 对提示“云端有相似记录”的待核对记录，首页待上传预览提供单条“忽略”操作。忽略后保留本机原始记录及体验，显示“已存本机，已忽略上传”，不再计入待上传提醒、不再尝试上传，也不再阻断对应日期的必经同步（必经仍以云端明细为准）。忽略状态在本机持久化，刷新、重启及缓存重建后继续生效；若云端随后按稳定身份确认了同一条记录，则正常显示已上传。账号切换、记录已上传或本机保存失败时不会错误地隐藏提醒，其他预览记录的上传名单保持不变。
- 同步必经不会补传本机记录；所选日期仍有正在上传或待上传记录时阻止提交，避免同步不完整的时长。正在上传时提示等待，待上传时提示到首页手动上传。其他日期的未上传记录不阻断所选日期。
- 待上传记录绑定首次使用的微信账号，云端同时校验 `expectedOpenid`。切换账号不会把这些记录上传给另一个账号。
- 手动补录首次上传仍受最近三个业务日的限制；过期失败保留本地记录与错误提示。已经成功上传的同身份重试返回原结果。
- 维护接口的 `dryRun` 保持只读，不创建 `meditation_locks`。
- `getAllRecords` 在整轮分页前后读取用户写入版本；分页期间发生事务增删时重新读取全部页，连续三轮变化则返回 `RETRY_REQUIRED`，不把遗漏记录的结果作为完整快照返回。旧环境缺少锁集合时仍可只读查询，不触发建表。

分页一致性保护覆盖会推进用户版本的静坐事务写入。直接在数据库控制台或其他未更新版本号的运维脚本中改数据，不在这项并发保护范围内；完成运维操作后需重新刷新。这项保护不执行历史数据迁移或清理。

## 首次上传和补传流程

1. 登录后的新记录在本机保存后异步检查网络，在线时才上传；离线或无法确认网络时保留待上传。网络持续可用时，可重试失败等待 100ms、最多额外重试三次；首次及每次重试各有独立的三秒期限（包含网络探测、文本检测与写入），100ms 等待不占用下一次尝试的期限。上传中不会先显示“待上传”；首页、记录页和计时完成页仅在校验感受和保存本机期间锁定提交控件并防止重复点击，保存后即可完成操作，不等待上传结果。本机保存失败时保留表单，允许以同一记录身份重试。
2. 冷启动和从后台返回时，并发读取云端与补传当天的明确待上传记录，慢读不会阻塞上传。历史待上传记录只在用户手动确认后补传。单独的网络恢复事件、进入首页、登录和下拉刷新仍只读取云端。
3. 首页“重试上传”先展示当前账号全部日期的待上传清单（包含旧版未确认记录），按日期列出时间、时长、心情及体验，并单独说明已明确无法上传或数据不完整的记录。确认后只尝试本次预览中的可重试记录，取消不上传，预览后新产生的待上传记录留待下次操作；账号切换后需重新查看清单。每条记录的每次上传尝试独立限时三秒，整批不再共用截止时间，并发点击复用同一请求。网络持续可用时，每条记录可重试的上传失败后等待 100ms，最多额外重试三次；重试期间保持“正在上传”，复用原始参数与记录标识。成功、账号切换、记录删除或刷新确认后停止重试；断网或网络探测失败会停止本轮及本批剩余上传，恢复网络也不继续。无效记录、超期、内容拒绝及需核对的旧记录不自动重试。重试次数耗尽后保留本机记录，等待下一次手动操作，不继续安排后台重试。
4. 新增另一条记录只尝试上传该新记录，不顺带上传此前失败的记录。重复提交同一个已保存身份也不会隐式补传。
5. 小程序重启后，已中断的“正在上传”状态恢复为待上传，再由打开流程补传当天记录，历史记录等待用户操作。后台结束的计时先同步保存本机及清除完成草稿，只保留计时结束及本机保存提示，上传结果不再更新提示，也不会在返回计时页时补弹上传结果。

小程序被关闭或系统挂起时，不假定定时器继续运行。游客记录登录后遵循相同日期规则：当天在下次打开时自动补传，历史仍须手动确认。手动补录若首次成功上传时已超出原有三天窗口，会保留本机并明确显示超期。

首页“待上传或待确认”数量与预览覆盖所有日期，不受“最近三天记录”列表的显示范围限制。新版依据上传标记和账号归属识别待上传记录；旧版没有云端 ID 的记录以未确认状态进入预览，确认时由云端核对。“全部”月度页仅查看记录，不提供上传入口；更早的记录统一从首页补传。

## 部署顺序

1. 先上传并部署 **`meditationManager`**，在云端安装依赖。必须先具备集合自愈、稳定身份去重、旧记录补传核对及账号校验，再让新版客户端发送重试请求。
2. 在测试环境验证一条新打卡的云端记录和统计，并验证打开小程序仅补传当天、历史只手动、单独恢复网络不重新启动上传，以及重试只保存一条。集合缺失场景应在隔离的测试环境检查，不删除线上锁集合来模拟。
3. 再上传、审核并发布包含待上传状态和重试队列的**小程序**。

无需先手动创建锁集合，也无需调用会检查所有集合的 `autoCreateCollections`。如果目标环境不允许云函数创建集合，可由管理员仅创建空的 `meditation_locks`，权限设为仅云函数/管理员可读写；不要为解决上传失败放宽客户端权限。恢复后新版待上传记录可重试。

本次只修改代码并做本地验证，尚未部署云函数或发布小程序。
