# 静坐来电中断保护

普通电话、微信语音或视频来电、系统闹钟等可能占用音频或让小程序切入后台。这些中断统一继续计时，包括接听后的通话期间；仅音频等待系统占用解除后恢复。切后台和进程被回收本身不代表本次静坐结束；是否结束仍以用户操作、微信明确报告的主动退出或计时到点为准。

## 行为

- 主动返回并卸载计时页，或微信明确报告用户退出小程序（`reason=0`）、进入其他小程序（`reason=1`）时，立即结束，按已静坐的整分钟保存；暂停时间不计入，不足一分钟不记录。主动离开后不继续累计，不在首页或重开时补响旧结束铃。
- 静默结算仅适用于上述主动离开。点击停止、自然到点、正计时达到上限，以及冷启动后发现已到点，都保留收坐提醒，遵循铃声/震动偏好；音频暂不可用时延后提醒，不能把播放失败当作已提醒。未知回调或尚未到点的到期回调不能提前结束会话。
- 原生功能页（`reason=2`）、其他原因（`reason=3`）及未提供原因的后台事件按被动中断保护：只保存检查点，保留同一次会话，不因中断立即生成完成记录。界面可停止刷新，运行中的逻辑时长仍按时间戳累计，未接来电响铃、已接听通话、闹钟占用音频期间均计入静坐。
- 被动中断期间卸载计时页仍保留活动会话；重建页面时恢复同一会话。`PageHide` 可能先于 `AppHide`，因此不凭 `PageHide` 单独判断主动离开。
- 原本已手动暂停的会话保持暂停，中断结束不会自动继续。
- 音频占用期间暂停起坐/引导音频；回到计时页且音频中断结束后从原进度继续。引导播放意图由代码保存，不依赖系统已暂停后的播放器状态。
- 本次会话的音乐选择、起坐等待状态和已确认的音频进度持久化到当前设备。页面重建或进程回收后，仅恢复匹配的活动会话，并在计时页可见且音频未被系统占用时按最后保存的状态续播；已暂停会话仍需手动继续。已播完的引导不因恢复而重播，已结束或取消的会话不能复活旧起坐、引导音频。进程突然退出且没有回调时，只能恢复此前已持久化的音频位置，不能保证逐帧衔接。
- 倒计时在后台到点，恢复时按原截止时刻完成一次，收坐提醒等待计时页可见且音频可播放，记录沿用现有确认保存流程。正计时保留原有 24 小时上限。
- 同一进程内临时中断或进程被回收后，正计时和倒计时均沿用原会话身份、开始时间和累计手动暂停时间。原状态为运行中时，冷启动按时间戳继续累计；原状态为手动暂停时，仍停在暂停时刻，直到用户继续。该恢复不依赖退出回调，进程未运行期间不会被当作用户手动暂停。倒计时若已超过截止时刻，则按原到点时间完成一次；正计时按原有 24 小时上限处理，不生成重复或被截短的记录。
- 未完成的收坐提醒与记录保存相互独立，经过被动中断、页面重建和冷启动仍保留。仅计时页可见且音频未被系统占用时播放，首页不响铃；主动离开、点击完成或完成并看日签后停止提醒。
- 开始、结束提醒继续分别遵循当前设备保存的偏好：铃声或约 3 秒震动；选择震动时不播放对应铃声。恢复会话不会重置这些偏好。
- 提示音播放期间持续检查可信进度，卡住或失败后从确认的位置重建一次；仍失败则提示并尝试震动，保留待提醒状态供下次回到计时页重试。震动提醒失败也保留待提醒，旧回调不能清除新会话的提醒。

## 平台能力边界

微信音频中断事件没有接听状态或中断来源字段，闹钟、电话、FaceTime、微信语音/视频、部分其他音频或原生页面会触发同一事件。公开 API 总览的电话分类仅提供拨打电话接口，不能可靠区分未接挂断与接听后挂断，也不能根据音频中断认定用户接听。当前产品规则已统一为接听、未接听和闹钟中断均继续计时，无需识别接听；用户仍可主动暂停或结束。`wx.onVoIPChatStateChanged` 监听的是小程序自身的实时语音房间，不可用于监测系统电话或微信聊天通话。

微信也没有提供手动锁屏、系统自动锁屏、切换应用的独立可靠标记，官方未保证这些操作在各版本、各系统对应的 `reason`。明确报告用户退出时按主动结束处理；若只报告 `reason=3` 或没有原因，则优先保护来电等被动中断，不根据系统遮挡或音频事件先后顺序猜测用户意图。需在 iOS 和 Android 真机分别验收这些操作，不能宣称所有手动锁屏都一定被识别为主动退出。

墙钟恢复保证的是重新运行后的计时计算，不代表 JavaScript 一直在后台执行。按微信运行机制，普通小程序进入后台约 5 秒后可能挂起，事件和接口回调在回到前台后触发；资源紧张或长期未使用时可能被销毁，销毁后完全终止运行。因此不能保证后台挂起或进程被回收期间准时响铃。已到点的会话会在恢复时完成一次，并在计时页可见且音频可用后补提醒；系统音频占用期间也不会强行播放。

`BackgroundAudioManager` 支持切后台前已经播放的音频继续播放，需要 `requiredBackgroundModes: ["audio"]`，正式版还需审核；官方同时限制后台通过 API 操纵音频播放状态，播放进度回调也仅在前台触发。它不能直接提供进程被回收后的自定义定时闹铃保证。本模块当前使用 `InnerAudioContext`，未接入后台音频管理器，也未声明后台音频能力。

## 实现与验证

App 将完整后台原因转交倒计时控制器；正计时采用相同的主动退出判断，计时页不再重复向倒计时控制器发送无原因后台事件。被动中断的检查点在首次后台事件同步写入，重复事件和延迟卸载不重置原开始时间或手动暂停状态；检查点不再作为冷启动自动暂停的边界。之后若收到明确主动退出，则按真实退出时刻结算一次。

正计时页在被动中断中卸载后，保留带进程身份的恢复检查点，并由 App 暂时接管明确主动退出的结算；新页面接回会话后解除接管。保存失败继续保留带原会话身份和结束时间的完成草稿供重试，不能恢复为继续累计的活动会话。音频中断期间手动暂停也会扣除已经运行的起坐准备时间，暂停期间不计入 5 秒等待。

自动测试覆盖后台原因、无原因兼容、计时恢复、暂停保持、音频事件先后顺序、前台纯音频中断、后台到点、页面重建后的引导/起坐进度、已结束音频不重播、新会话从头播放、冷启动检查点及重复保存保护。

本轮新增自动测试覆盖运行中跨进程继续、手动暂停跨进程保持、无退出回调直接回收、倒计时冷启动前已到点、原截止时刻入账、音频持久化恢复、收坐提醒与记录均不重复。重复前后台与音频事件不能提前终止会话；记录保存失败不清除待提醒。音频状态首次读取失败后会在恢复时重试，已领取的音频不会因重复页面回调重新播放。模拟时钟可以验证状态和时间计算，不能证明系统挂起期间执行了 JavaScript，也不能证明真实来电或闹钟事件已验收。

进程回收后只打开首页、尚未进入计时页就明确退出时，也会静默结算原会话，无需提前加载倒计时控制器。结算先保存终态及内嵌完成草稿，使用原会话身份入账；保存失败保留草稿，不能在下次恢复时重新开始累计。正计时页可恢复终态中的草稿备份，独立草稿未写成功前不删除该备份。

专项 review 增加了来电响铃过程中每 15 秒直接读取逻辑时长的验证，确认未接来电未结束、尚未回前台时也继续累计。中断检查点写盘失败时，同进程恢复优先使用匹配会话及运行时的内存副本；恢复关键存储读取失败时保留原检查点，回到计时页或前台后再尝试恢复，不能将读取失败当作空会话并覆盖。完成弹窗、提示或其他界面副作用失败不阻断待播结束铃。铃声确认暂时写盘失败后，后续访问会有界补写，避免冷启动重复提醒。已观察到的手机时间回拨会同步校正倒计时的时间基准，避免生成无效检查点后静默丢失进度。

## 真机验收

### 2026-11-06 系统复核

本轮在现有未提交修改上审查正/倒计时状态机、页面与 App 生命周期、暂停和上限、记录确认与恢复、音频资源与原生回调、提醒偏好及亮度控制。先运行全量基线（3195 项通过），再对下列缺口补充失败复现和回归修复：

| 优先级 | 已修复问题 | 现在的行为 |
| --- | --- | --- |
| P1 | 正计时运行中或页面交接后设备时间回拨，时长倒退、检查点失效 | 校正时间锚点，保留已确认进度和暂停状态 |
| P1 | 正计时完成草稿写入失败后，唯一恢复检查点被清空 | 页面和 App 都保留含草稿的终态，独立草稿持久化或入账确认后再清理 |
| P1 | 关键存储读取失败被当成空会话，可能覆盖原计时 | 初始化可继续，恢复可重试；恢复未完成前保护开始、重置和模式/时长变更 |
| P1 | 倒计时恢复读取失败期间主动退出，恢复后继续累计 | 记住首次明确退出时刻，读取恢复后按原边界结算 |
| P2 | 暂停时显示陈旧时长，24 小时边界仍可暂停成活动会话 | 暂停前同步时长，到达上限直接完成 |
| P2 | 已入账但清理失败，误报保存失败或冷启动再弹完成草稿 | 分离入账和清理；保存终态与本机账本共同确认，读取失败保守保留草稿 |
| P2 | 返回前台补写完成草稿覆盖用户刚填写的感受 | 只补写缺失草稿，已存在的同会话文本保持原样 |
| P2 | 旧引导播放器事件污染下一轮，迟到的云地址导致不播放 | 新会话撤销旧播放器身份，保留等待地址的播放意图并按可播放状态接续 |
| P2 | 引导备用路径不存在，运行中选择无音乐未立即生效 | 移除无效资源路径，失败时提示；无音乐立即暂停，重新选择可续播 |
| P2 | 明确关闭提醒时首次读取失败，旧铃在以后恢复 | 持久化最新撤销意图，失败后有界重试 |

最终验证：`npm run test:timer` 423 项全部通过，`npm test` 3233 项全部通过，较基线新增 38 项回归测试；修改的 JavaScript 语法检查与 `git diff --check` 通过。

测试模拟时间、存储故障、原生音频事件和页面/App 回调；本轮没有发布小程序或部署云函数。真机验证仍按下方清单执行，尤其首次收坐铃、通话、锁屏及音量/静音状态。系统挂起期间准时出声仍受微信后台运行能力限制；全部持久化渠道同时不可用且进程被回收时，内存中的新状态无法保证恢复。

以下项目需在 iOS 和 Android 上分别验证，保留机型、系统版本、微信版本、实际 `reason`、音频事件顺序和观察结果。开发者工具和模拟测试不能替代真机验收；此清单不表示所有项目已经通过。

- 普通电话、微信语音、微信视频：分别覆盖未接自然挂断、拒接、接听后挂断；每组覆盖有/无引导音频、运行中及已手动暂停状态。核对接听与未接听均继续累计运行时长、会话身份不变和音频位置正确，也不因中断结束自动恢复手动暂停的会话。
- 系统闹钟：覆盖响铃、停止、稍后提醒，以及音频中断先于或晚于页面隐藏的实际顺序。核对计时继续累计、音频占用期间不抢播、回到计时页且占用解除后续播。
- 锁屏、系统自动锁屏、切换应用：记录实际后台原因；明确退出按退出结算，其余按被动中断保护。不得仅依据操作名称推断回调原因。
- 直接进程回收且没有退出回调：分别在起坐准备、起坐提醒、引导播放和手动暂停时回收；重开后检查运行中按原时间戳继续、暂停保持、音频从已保存位置恢复，且不出现额外短记录。
- 冷启动时倒计时已经到点：保持关闭直至超过截止时间，再重开首页和计时页。检查结束时间仍为原截止时刻、完成记录只生成一次、首页不响铃，进入计时页且音频可用后按铃声/震动偏好补提醒。确认保存、再次进入或再次冷启动后不得重复入账或重复已完成提醒。
- 系统音频占用横跨截止时刻、铃声播放中再次被闹钟/来电中断：验证待提醒保留、占用结束且计时页可见后恢复；主动离开或确认完成后停止旧提醒。

## 官方接口依据

- [wx.onAppHide](https://developers.weixin.qq.com/miniprogram/dev/api/base/app/app-event/wx.onAppHide.html)：后台原因的四类取值。
- [音频中断开始](https://developers.weixin.qq.com/miniprogram/dev/api/base/app/app-event/wx.onAudioInterruptionBegin.html)、[音频中断结束](https://developers.weixin.qq.com/miniprogram/dev/api/base/app/app-event/wx.onAudioInterruptionEnd.html)：系统音频占用与恢复，未提供通话接听状态。
- [API 总览](https://developers.weixin.qq.com/miniprogram/dev/api/index.html)、[wx.onVoIPChatStateChanged](https://developers.weixin.qq.com/miniprogram/dev/api/media/voip/wx.onVoIPChatStateChanged.html)：电话接口范围与小程序自身语音房间状态。
- [小程序运行机制](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/operating-mechanism.html)：前后台、挂起、销毁与恢复机制。
- [wx.getBackgroundAudioManager](https://developers.weixin.qq.com/miniprogram/dev/api/media/background-audio/wx.getBackgroundAudioManager.html)、[BackgroundAudioManager](https://developers.weixin.qq.com/miniprogram/dev/api/media/background-audio/BackgroundAudioManager.html)、[requiredBackgroundModes](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app.html#requiredBackgroundModes)：后台续播条件、播放控制限制及正式版审核要求。
