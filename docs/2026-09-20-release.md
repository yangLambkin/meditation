## 旧数据迁移（先预览）

通过云开发控制台/受信任运维调用 `meditationManager`，不要从小程序调用。接口拒绝具有微信 `OPENID` 的客户端请求。

默认参数为只读预览：

```json
{ "type": "migrateBusinessDates", "dryRun": true }
```

返回 `data.users` 中每位用户的 `dateChanges`、仅按稳定身份识别的 `duplicates`、`resultingRecordCount`。每页扫描 100 条记录，处理其中用户的完整历史。同一用户可能出现于多页，报告是每页快照，不宜简单相加计算全站人数。`data.nextCursor` 非空时，把它作为下一次 `afterId` 继续预览：

```json
{ "type": "migrateBusinessDates", "dryRun": true, "afterId": "上页的 nextCursor" }
```

检查报告后，先备份 `meditation_records`、`user_stats`、`experience_records`，保存导出与预览报告。确定执行时从第一页重新开始，**显式**传入 `dryRun:false`，逐页使用返回的 `nextCursor`，直到其为 `null`：

```json
{ "type": "migrateBusinessDates", "dryRun": false }
```

执行内容：

- 普通计时记录按原始 `timestamp` 重新归入北京时间 `[02:00, 次日02:00)`；显式 `source:'manual'` 或 `dateSource:'manual'` 的记录保留选择的业务日期。
- 仅合并相同用户、相同 `localId`/`idempotencyKey` 的重复行，合并保留心得，重算次数、日/月时长、天数、连续天数。
- 不按相同时间、时长或文本推测重复。无稳定身份的旧重复记录无法可靠自动清理，保留供用户确认后长按删除。
- 每位用户的记录、统计、版本号在同一事务中提交；事务内仅用文档操作，事务外的分页快照通过版本校验避免并发遗漏。迁移可重复执行。

完成后抽查 01:59/02:00、月底/年末、连续天数、手动补录、团队统计与同步预览。旧外部系统按 04:00 规则上报的历史数据不会由本迁移修改；需要核对外部系统的覆盖语义后重新同步最近可选日期。更久历史若需更正，走外部系统支持的运维流程；本次未执行重报。

## 记录与离线同步约定

`recordCheckin(duration, [], experience, timestamp, options)` 第五参数支持计时会话字符串，或 `{ idempotencyKey, source:'manual'|'timer', date }`。同一次提交/计时结束始终复用身份；下一次真实静坐使用新身份。云端将用户与身份组合成稳定文档 ID，重复请求不重复写记录/心得/统计。静坐时长为 1–1440 分钟整数，正计时最长 24 小时。

新版标记为 `syncVersion: 1` 的计时记录可在长期离线后补传；旧本地记录不会仅因缺少云端 ID 被自动加入队列。逐条上传避免每用户并发版本冲突。手动补录在前后端均限制最近三个业务日。已成功上传的同身份请求过期后仍返回原结果；首次上传时已超出窗口的离线手动补录不会绕过校验，保留本地记录与 `syncError` 提示，不静默丢弃。
