# 功课记录与静坐镜像

## 当前实现与约定

本次增加「记录」tab、五类功课表单、混合明细、月度及累计统计、单项日历，以及静坐到 data 的独立镜像分支。首页沿用原布局、日历、每日金句及静坐录入弹窗，仅调整开始静坐/记录功课入口并增加记录页入口。团队、勋章、静坐原统计及旧按日同步继续沿用原逻辑。

记录页按「明细 / 统计 → 功课与月份筛选 → 记录内容」组织。全部功课的统计顶部逐项展示功课名称及本月记录件数，每条记录计 1 件，已上传功课累计中的各项也显示记录件数，不汇总分钟、次数等不同单位的功课量。选择单项后，顶部展示功课名称和所选月份的累计时间；即刻觉察和日行一善分别显示累计次数、累计件数。下方月历使用与页面一致的暖金色边框、棕色文字及「周一」至「周日」表头，保留现有月份筛选，不重复展示功课名称与月累计。全部功课月历按记录件数汇总，日期下方显示「+数值件」；单项月历按该项功课计算，显示不带单位的「+数值」，辅助阅读说明保留精确值和单位。达到万的累计值使用「万」缩写，无记录日期、未来日期及月首月尾空白格不显示数值，日期行仍保留相同高度。日期圆形按当月已发生日期的相对累计量显示五档金棕色深浅，今日及选中日期另有主题色边框高亮，底部提供「少—多」图例和点击提示；点击日期下钻当天明细。月历下方不再显示「查看本月明细」按钮，也不提供「更多统计」或收起控件；单项功课的每日完成量趋势与已上传功课累计直接展示。

「记录」tab 使用与其他 tab 一致的灰色 / 暖金色线性记录本图标。设置入口统一放在「我 → 功课入口设置」，六类功课默认全部显示，可逐项隐藏或恢复全部。设置仅控制首页「记录功课」及记录页「＋记录功课」的录入选项，不影响计时、首页开始静坐、已有记录、统计、编辑或待上传任务。偏好按微信账号分别保存在当前设备（未登录时使用独立本机设置），不进行云端同步；读取异常回退全部显示，写入失败会提示并恢复原开关。允许全部隐藏，此时录入入口会提示前往设置。

按本次明确要求，**任何云函数均未修改**。小程序通过 `wx.request` 直连测试环境 `https://data.bjzl.net.cn/api/openapi/practices/...`。授权暂沿用放在包内的服务令牌，不实施方案中的绑定断言、个人凭证或登录改造。共享令牌与学号选择头不构成个人身份验证；了解此限制后再发布。集中配置在 `miniprogram/utils/practiceConfig.js`，`baseUrl` 只填域名，不包含网页路径 `/records`；该配置独立于旧静坐同步云函数的 `BIJING_API_BASE`。后续登录改造入口为 `practiceAuth.js`。

## 发布顺序

1. 先发布 bijing-data 中的兼容 OpenAPI 和来源只读展示。DDL 新增 `practice_record_sources`、`practice_record_operations`，已维护在该仓库的 `bijing_data_ddl.sql`，应用会按现有模式初始化。接口说明见 bijing-data 的 `docs/openapi-practices.md`。
2. 在小程序后台确认合法 request 域名包含 `https://data.bjzl.net.cn`。
3. 在微信开发者工具验证绑定学号的五类新增/编辑/删除、计时及手动静坐、断网恢复，再发布小程序。服务尚未发布时，新接口可能失败并保留待办，不代表原静坐保存失败。

本次代码未部署到 data，也未上传或发布小程序。`practicesEnabled` 与 `sittingMirrorEnabled` 为两个独立开关，当前代码均为 true；发布前可关闭任一功能，已保存任务会保留并暂停发送。关闭镜像不修改原静坐成功条件或旧同步。

## 记录页的读取失败提示

明细与统计共用同一套错误状态：本机账号或学号绑定缺失时，引导前往「我」；服务凭证被拒绝或接口尚未部署时，显示「功课服务暂未就绪」并提供重新加载。原「重新授权」只会再次核对本机绑定，无法恢复未部署的服务，因此已移除。服务问题无需用户反复解绑或重新登录。

2026-10-31 联调中，同一服务凭证访问旧用户接口能到达业务层，新功课 feed/summary 却返回登录过期的 401。需先发布 bijing-data 的功课路由及 OpenAPI 白名单，再验证真实记录读取；小程序页面修复本身不代表后端已经发布。

## 数据与恢复

- 日期和时间使用实际北京时间自然日。原静坐仍按凌晨 02:00 分日；data 镜像从实际时间直接取自然日期。
- 新功课首次提交前持久化操作身份与表单快照，重试沿用原请求标识和发生时间。已发送的未知结果不能仅删本机状态，须先确认来源再完成删除。
- 待办使用独立 `practice_outbox_v1` 存储，固定微信账号、学号及绑定版本；换账号或换绑暂停旧任务。关闭小程序后不承诺后台执行，清除本机数据会失去未确认任务。
- 静坐原云请求前登记等待确认意图。新增或更新在原云返回成功或完整读取复核后，获取源云 ID、可靠更新时间和体验正文，再发送镜像；删除在原云成功确认后按源 ID 直接调用 OpenAPI，旧待办可通过完整读取确认来源不存在后恢复。镜像失败不回滚原静坐。
- 来源镜像在 data 的个人与管理入口只读。服务端按成员、来源、源 ID 去重，删除保留墓碑，迟到的新增或更新不能恢复已删记录。
- 日行一善复用「做善事」，新建一件，编辑保留原件数及附件等关联数据，内容和感悟对已登录成员可见。
- 待上传数据与 data 已确认统计分开展示。静坐历史不自动全量迁移，记录页累计不代表原静坐完整历史。

## 保守保留的情况

新增或更新缺少真实发生时间、可靠源版本、完整源读取或体验正文时，镜像保留为待核对，不伪造上传时间，不将体验文档 ID 当正文。旧独立体验删除没有更新静坐版本，也没有可靠删除回执；这类操作会明确保留待核对。若未来需要彻底消除此限制，应另行确认云端变更证据方案，再决定是否改云函数。整条静坐记录的删除无需源版本，按下文的 OpenAPI 删除流程恢复。

## 静坐删除镜像凭据权限修复

2026-10-31 真机出现「删除 · document.get:fail cannot find document with _id md_...」待上传错误。原静坐已经返回删除成功并保存了 `deletionId`；本机快照不含 `createdAt/updatedAt` 时，旧恢复流程直接从小程序读取 `meditation_locks` 删除凭据。但该集合仅允许云函数访问，无权限读取也会显示上述「文档不存在或无权限」错误，导致 data 副本仍显示，删除镜像一直保留在队列。

修复后原静坐返回删除成功及对应源记录 ID，即直接调用 `DELETE /api/openapi/practices/sitting/sources/meditation/{sourceRecordId}`。请求沿用原 `Idempotency-Key` 与同值 `operationId`；有可靠源版本则继续携带，没有则省略 `sourceVersion`。OpenAPI DELETE 保留原版本并写永久删除标记，迟到 PUT 不能复活；PUT 继续强制可靠源版本。整个修复不读取锁集合、不修改云函数，也不伪造源时间。

已有 `practice_outbox_v1` 删除待办在完整云端快照确认原记录不存在后，沿用原源 ID 和请求身份直接重试 OpenAPI 删除；未完整读取、源记录仍存在或当前账号不匹配时保留任务。先部署支持 DELETE 省略版本的 bijing-data，再更新小程序，进入记录页或点击「重试上传」即可恢复。成功后移除对应 data 副本和待办，无需清除小程序缓存或重新创建静坐记录，无需部署云函数。

2026-10-31 已将 bijing-data 修复 `3a0e019` 合入并推送 `release_v1.0.0`，部署到测试环境 `https://data.bjzl.net.cn`。部署脚本成功结束，页面及公开 OpenAPI 均返回 HTTP 200；运行容器的构建代码和公开协议均确认 DELETE 允许省略 `sourceVersion`。小程序云函数目录无修改；手机上原待办的实际删除结果仍需点击「重试上传」确认。
