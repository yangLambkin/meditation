# 功课记录与静坐镜像

## 2026-11-04：功课展示与统计的分日口径

功课首页今日累计、最近三天分组，以及「查看全部」中的明细筛选、当日统计、月度日历、趋势和累计功课天数，统一按北京时间每日 02:00（含）至次日 02:00（不含）归属当天。页面在可见时跨 02:00 自动刷新；月初 02:00 前仍展示上月当日。没有实际发生时间的旧记录保留原日期。

仅读取时使用独立的 `displayDate`；原始 `recordDate`、`occurredAt`、新建/编辑表单及近 14 个自然日的补录范围保持实际日期时间。小程序 feed/summary 查询显式传 `dayStartHour=2`，依赖 bijing-data 对应接口发布；接口默认仍为自然日，其他调用不受影响。本次未部署 data 或发布小程序。验证通过：小程序全量 2604 项、data 功课接口 30 项、data TypeScript 与局部 ESLint、页面 WXML 编译。

## 当前实现与约定

本次增加「记录」tab、五类功课表单、混合明细、月度及累计统计、单项日历，以及静坐到 data 的独立镜像分支。首页沿用原布局、日历、每日金句及静坐录入弹窗，仅调整开始静坐/记录功课入口并增加记录页入口。团队、勋章、静坐原统计及旧按日同步继续沿用原逻辑。

记录首页以今天为主：只展示「记录设置」中已选功课的今日累计卡片，点击卡片直接录入对应功课，静坐继续使用原首页录入弹窗。六项全部开启时以三列两行展示六格，下方统一显示北京时间今天、昨天和前天的记录；只开启部分功课时，下方仍显示这些功课最近三天的明细。卡片累计独立读取当天完整汇总，列表读取完整日期范围的所有分页后按当前显示设置过滤，不以已载入条数代替累计量。返回页面、下拉刷新或上传成功后更新；跨月、跨年均按北京时间 02:00 分日。首页顶部左侧将「今日功课」与月日（如「11月1日」）展示在同一行，空间不足时日期可换行，下方以浅灰小字提示「点击功课卡片，记录今日练习」；整体组成紧凑文字组，与右侧「＋ 记录」按钮垂直居中对齐，明细与统计页不再显示录入按钮。「最近三天记录」标题右侧统一提供「查看全部」入口，打开独立明细与统计页面，不再单列两个入口或显示「北京时间 · 已上传」提示；全部隐藏时仍保留查看入口及选择功课的提示。首页待上传提示默认折叠，展开后可查看和重试。

记录首页在同一账号、绑定及北京时间 02:00 分日的同一日内返回、下拉刷新或收到上传成功通知时，保留上次成功读取的今日累计、卡片完成底色及最近记录，后台继续请求最新数据；数值未变化时不重复更新卡片，最近记录在完整分页读取成功后替换。首次加载使用占位，成功的零值也视为已加载。跨日、切换账号或绑定、账号信息读取失败时清空旧展示，并忽略旧请求；网络刷新失败保留上次结果并提示重试，绑定或身份错误则清空相应数据并引导确认绑定。显示项目变更立即按最新设置过滤已读取的完整数据，不持久化统计缓存，也不跳过后台请求。

独立的明细与统计页按「明细 / 统计 → 功课与月份筛选 → 记录内容」组织，保留原有历史数据及管理功能。全部功课不在日历上方重复展示各项统计，仅在下方「已上传功课累计」中逐项展示实际累计量，并附所选月份的本月总数：静坐、走路觉察、熏习和禅拍使用分钟，即刻觉察和日行一善使用次，不以记录条数替代实际完成量。日行一善仅统计展示单位使用「次」，原善事件数及表单、明细单位保持原语义。选择单项后，顶部展示功课名称和所选月份的累计时间或累计次数。下方月历使用与页面一致的暖金色边框、棕色文字及「周一」至「周日」表头，保留现有月份筛选，不重复展示功课名称与月累计。全部功课月历按记录条数汇总，日期下方显示「+数值条」；单项月历按该项功课计算，显示不带单位的「+数值」，辅助阅读说明保留精确值和单位。达到万的累计值使用「万」缩写，无记录日期、未来日期及月首月尾空白格不显示数值，日期行仍保留相同高度。日期圆形按当月已发生日期的相对累计量显示五档金棕色深浅，今日及选中日期另有主题色边框高亮，底部提供「少—多」图例和点击提示；点击日期下钻当天明细。月历下方不再显示「查看本月明细」按钮，也不提供「更多统计」或收起控件；单项功课的每日完成量趋势与已上传功课累计直接展示。

「记录」tab 使用与其他 tab 一致的灰色 / 暖金色线性记录本图标。在「我 → 记录设置」中统一提供「显示记录」开关和各类功课入口设置。「显示记录」默认开启：开启时显示「记录」tab、首页「记录功课」；关闭后底栏显示首页、计时、团队、我，首页保留「记录静坐」。「记录设置」入口始终保留，关闭记录后仍可进入重新开启；各类功课选择会保留，修改功课选择或「显示全部功课」不会改变总开关。开关立即生效，按账号保存在当前设备；未设置时默认显示，已保存的关闭选择继续保留；读取失败按关闭处理，保存失败恢复原状态并提示。使用自定义底栏支持四 / 五项切换，保留原图标、选中状态、安全区留白和「我」页提醒红点，不影响已有记录、统计或待上传任务。

功课入口设置中的六类功课默认全部显示，可逐项隐藏或恢复全部。设置控制首页「记录功课」、记录页「＋记录功课」的录入选项、类型筛选和当日统计的显示项目，不影响计时、首页开始静坐、已有记录、月度及累计统计、编辑或待上传任务。偏好按微信账号分别保存在当前设备（未登录时使用独立本机设置），不进行云端同步；读取异常回退全部显示，写入失败会提示并恢复原开关。允许全部隐藏，此时录入入口及当日统计会提示前往设置。

静坐同步与上述显示设置独立：隐藏整个「记录」入口或隐藏「静坐觉察」功课后，首页「记录静坐」及「开始静坐」的保存仍会经过原云端确认，再发送到 data；无需打开记录页。计时在前台结束后，点击「完成」或「完成并看日签」保存实际静坐整分钟数及结束时间，暂停不计入时长；不足一分钟及取消操作沿用不记录规则。同步要求当前账号已登录并绑定学号，且独立的 `sittingMirrorEnabled` 开启。网络失败时保留待办，返回小程序或网络恢复后自动续传，不会改用重试时间覆盖原结束时间。

新增集成回归覆盖隐藏入口后的手动添加、正计时和倒计时完成确认，以及未进入记录页时通过 App 恢复待办。核对实际 OpenAPI 请求的来源 ID、分钟数、发生时间和幂等标识。测试发现并修复发送前来源读取重复触发恢复的问题：内部核对不再触发镜像观察，没有新来源确认的快照不再启动发送，恢复过程复用同一轮发送结果；单轮失败最多尝试三次，下一次外部恢复触发继续使用原请求。

按本次明确要求，**任何云函数均未修改**。小程序通过 `wx.request` 直连生产环境 `https://data.bijing.life/api/openapi/practices/...`。授权暂沿用放在包内的服务令牌，不实施方案中的绑定断言、个人凭证或登录改造。共享令牌与学号选择头不构成个人身份验证；了解此限制后再发布。集中配置在 `miniprogram/utils/practiceConfig.js`，`baseUrl` 只填域名，不包含网页路径 `/records`；该配置独立于旧静坐同步云函数的 `BIJING_API_BASE`。后续登录改造入口为 `practiceAuth.js`。

## 明细页的当日统计

明细页每个日期右侧提供「查看统计」，点击以简洁弹窗展示当天功课的累计量、记录条数及有记录的功课项数。弹窗遵循「我 → 记录设置」的显示选择，已隐藏功课不展示，记录条数与功课项数也仅计算显示中的功课；全部隐藏时提示前往记录设置开启。分钟与次数沿用统计页口径，未练习项显示 0；只统计已上传记录。弹窗按所选日期单独请求全部功课汇总，再按当前账号最新的显示设置展示，不受列表的类型筛选或分页影响。读取失败可单独重试，关闭弹窗、刷新、离开页面或切换账号后不会应用旧请求结果。

## 记录页微信分享

「记录」页通过微信小程序右上角的三点菜单分享，支持发送给朋友及分享到朋友圈，页面内不显示分享按钮。分享使用固定标题和包内封面，不附带发送者的账号、学号、记录、感悟、草稿或当前筛选条件；收件人打开后沿用自己的账号读取自己的记录，未绑定账号时继续显示原绑定引导。

## 数据与恢复

- 日期和时间使用实际北京时间自然日。原静坐仍按凌晨 02:00 分日；data 镜像从实际时间直接取自然日期。
- 五类新功课（走路觉察、即刻觉察、熏习、日行一善、禅拍）默认发生日期为今天，可补录北京时间最近 14 个自然日（含今天，即今天及此前 13 天）；日期选择器及保存校验使用相同范围。跨日后未提交且超出范围的草稿会提示重新选日期并保留内容，历史记录仍可编辑，已入队记录跨日重试沿用原日期、时间及请求身份。静坐觉察沿用原补录规则。
- 新功课首次提交前持久化操作身份与表单快照，重试沿用原请求标识和发生时间。已发送的未知结果不能仅删本机状态，须先确认来源再完成删除。
- 待办使用独立 `practice_outbox_v1` 存储，固定微信账号、学号及绑定版本；换账号或换绑暂停旧任务。关闭小程序后不承诺后台执行，清除本机数据会失去未确认任务。
- 静坐原云请求前登记等待确认意图。新增或更新在原云返回成功或完整读取复核后，获取源云 ID、可靠更新时间和体验正文，再发送镜像；删除在原云成功确认后按源 ID 直接调用 OpenAPI，旧待办可通过完整读取确认来源不存在后恢复。镜像失败不回滚原静坐。
- 来源镜像在 data 的个人与管理入口只读。服务端按成员、来源、源 ID 去重，删除保留墓碑，迟到的新增或更新不能恢复已删记录。
- 日行一善复用「做善事」，新建一件，编辑保留原件数及附件等关联数据，内容和感悟对已登录成员可见。
- 待上传数据与 data 已确认统计分开展示。静坐历史不自动全量迁移，记录页累计不代表原静坐完整历史。

## 保守保留的情况

新增或更新缺少真实发生时间、可靠源版本、完整源读取或体验正文时，镜像保留为待核对，不伪造上传时间，不将体验文档 ID 当正文。旧独立体验删除没有更新静坐版本，也没有可靠删除回执；这类操作会明确保留待核对。若未来需要彻底消除此限制，应另行确认云端变更证据方案，再决定是否改云函数。整条静坐记录的删除无需源版本，按下文的 OpenAPI 删除流程恢复。

## 静坐删除镜像凭据权限修复

2026-10-31 真机出现「删除 · document.get:fail cannot find document with _id md_...」待上传错误。原静坐已经返回删除成功并保存了 `deletionId`；本机快照不含 `createdAt/updatedAt` 时，旧恢复流程直接从小程序读取 `meditation_locks` 删除凭据。但该集合仅允许云函数访问，无权限读取也会显示上述「文档不存在或无权限」错误，导致 data 副本仍显示，删除镜像一直保留在队列。

修复后原静坐返回删除成功及对应源记录 ID，即直接调用 `DELETE /api/openapi/practices/sitting/sources/meditation/{sourceRecordId}`。请求沿用原 `Idempotency-Key` 与同值 `operationId`；有可靠源版本则继续携带，没有则省略 `sourceVersion`。OpenAPI DELETE 保留原版本并写永久删除标记，迟到 PUT 不能复活；PUT 继续强制可靠源版本。整个修复不读取锁集合、不修改云函数，也不伪造源时间。

已有 `practice_outbox_v1` 删除待办在完整云端快照确认原记录不存在后，沿用原源 ID 和请求身份直接重试 OpenAPI 删除；未完整读取、源记录仍存在或当前账号不匹配时保留任务。先部署支持 DELETE 省略版本的 bijing-data，再更新小程序，进入记录页或点击「重试上传」即可恢复。成功后移除对应 data 副本和待办，无需清除小程序缓存或重新创建静坐记录，无需部署云函数。

2026-10-31 已将 bijing-data 修复 `3a0e019` 合入并推送 `release_v1.0.0`，部署到测试环境 `https://data.bjzl.net.cn`。部署脚本成功结束，页面及公开 OpenAPI 均返回 HTTP 200；运行容器的构建代码和公开协议均确认 DELETE 允许省略 `sourceVersion`。小程序云函数目录无修改；手机上原待办的实际删除结果仍需点击「重试上传」确认。

## 正式环境删除同步恢复

2026-10-31 小程序切换至 `https://data.bijing.life` 后，首页删除静坐出现「sourceVersion 须为可靠的源更新时间毫秒数字字符串，不能晚于当前时间」。正式服务当时仍运行 `e615536`，公开协议也仍要求 DELETE 必填 `sourceVersion`；测试环境已经部署上述兼容修复。本机刚录入的静坐缓存没有原云端创建/更新时间，删除请求因而只携带 `operationId`，被旧正式接口拒绝，并以 `blocked` 状态保留。
