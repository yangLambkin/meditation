# 记录静坐：分钟循环选择

原入口使用微信原生 `picker mode="time"`。截图中分钟停在 59、下方留白，与原生控件的非循环行为一致；页面没有限制分钟范围。微信没有提供循环属性，因此开发者工具和不同手机上的原生交互可能不同，不能用单台设备的表现排除这个问题。

参考：[picker](https://developers.weixin.qq.com/miniprogram/dev/component/picker.html)、[picker-view](https://developers.weixin.qq.com/miniprogram/dev/component/picker-view.html)。

## 实现

- 首页改用独立 `time-picker` 组件，小时为 00–23，分钟显示重复的 00–59，支持 59→00 和 00→59。分钟跨界不自动改变小时或归属日期。
- 分钟使用五轮列表，打开时定位中间轮；滚入外围轮后在停止时回中，保持相同分钟。一次极长的甩动仍可能到达列表物理边界，需在真机检查惯性体验。
- 滚轮操作只更新组件草稿，确定后才写回表单。取消或点击遮罩不修改已选时间。选择期间冻结首页当前时间的自动更新。
- 等待滚动结束及短暂事件缓冲后才允许确定，兼容 `change` 和 `pickend` 的先后差异；卸载、取消和新手势会使旧回调失效。

## 验证

运行 `npm run test:home-checkin`。组件测试覆盖双向跨界、两方向连续八圈、小时边界、事件顺序、快速确认、取消重开、过期回调和程序回中事件。页面测试覆盖草稿期间不能提交、确认保存、取消保留自动时间与手动时间、关闭重开和提交锁。

微信开发者工具已编译并加载新选择器，WXML/WXSS 编译通过。自动化状态测试不等同于真机滚动验证；发布前在安卓和 iPhone 检查：

1. 选 06:59，分钟继续向后到 00；从 06:00 向前到 59，小时均保持 06。
2. 连续滚动多圈、快速甩动、滚动中点击确定，确认最终字段与停稳后的滚轮一致。
3. 取消、点击遮罩、重开后值正确；选择跨过一分钟后不被当前时间刷新打断。
4. 确认 01:59、02:00、23:59 时保留现有归属日期规则；未来时间仍不能提交。
5. 短屏、键盘收起与底部安全区不遮住按钮，滚动不会穿透到背景表单。
