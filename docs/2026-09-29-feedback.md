# 用户反馈与管理员处理

“我 → 意见反馈”提供反馈表单和本人的反馈记录。反馈内容必填，最多 1000 字；联系方式选填，最多 100 字。未登录用户可先填写，登录返回后保留本页草稿。提交成功后清空表单，失败时保留内容供重试。

管控中心新增“用户反馈”页签，默认显示待处理反馈，可切换处理中、已处理及全部，按提交时间从新到旧分页查看。管理员展开反馈后可修改处理状态、填写回复并保存；用户在“我的反馈”中查看最新状态和回复，可下拉刷新。回复为可选项，最多 1000 字。

管理员展开任意状态的反馈后，可点击“删除反馈”，确认后永久删除该反馈及其处理回复。删除后管理员列表立即移除该项，用户刷新反馈记录后也不再看到它。取消确认不删除；删除失败保留列表和编辑草稿，供管理员重试。删除与保存互斥，避免重复操作；确认期间离开页面或切换页签，不会继续发出删除请求。

底部“我”图标同时承载管理员待办和用户处理结果提醒，“我”页面内的对应入口分别显示各自来源的红点：

- 用户提交反馈后，存在待处理或处理中的反馈时，管理员看到红点；同步异常也会点亮管理员红点。仅查看反馈不会消除管理员待办。管理员保存处理结果后立即刷新提醒；全部反馈均已处理、没有同步异常，且该管理员本人没有未读反馈结果时，红点消失。
- 管理员将反馈标记为已处理后，提交该反馈的用户看到红点。用户进入“意见反馈”，处理结果成功显示并确认已读后，刷新提醒；还有尚未加载的未读结果时，红点保留，分页加载并显示后再确认已读。只进入“我”页面不会将反馈标记为已读。
- 已处理反馈的回复发生变化时，再次提醒用户；不修改状态或回复而重复保存，不重新点亮红点，也不改变内容版本。重新改为待处理或处理中会撤回该结果的未读提醒，再次标记为已处理时重新提醒。

“意见反馈”（提交反馈入口）仅在本人有未读处理结果时显示红点；“当前版本”（管理员入口）仅在有管理员待办时显示红点，来源包括待处理或处理中的反馈及同步异常。用户确认已读后，反馈入口红点随未读状态更新；管理员处理完待办后，版本入口红点随管理员提醒更新。底部“我”红点合并这两个来源，因此一个入口消点后，另一个入口仍有提醒时，底部红点继续保留。仅进入“我”页面或点击版本入口不会清除提醒。

红点只在打开小程序或从后台返回前台时自动刷新一轮，同一次前台期间重复收到打开通知也不会重复查询。进入“我”、切换底部页面以及页面首次渲染只使用内存中的提醒状态，不额外请求云端。管理员也可能是反馈提交人，两种提醒合并显示，任一来源仍有待办或未读结果，红点就保留。

| 场景 | 红点刷新频率 |
| --- | --- |
| 打开小程序、从后台返回 | 每次一轮，两个云函数各调用一次，并行执行 |
| 进入“我”、切换页面、同一次前台的重复打开通知 | 不查询，显示缓存 |
| 停留前台 | 不轮询，无刷新定时器 |
| 管理员保存或删除成功、用户确认未读结果已读成功 | 主动刷新一轮，核对剩余提醒 |
| 登录身份变化、新绑定后确认管理员权限 | 主动刷新一轮，避免使用旧身份的提醒 |
| 请求失败或超时 | 不自动重试，等待下一次有效触发 |

每轮分别调用 `adminManager/getSyncAlert` 和 `meditationManager/getFeedbackAlert`。三个提醒存在性查询均最多读取一条记录，只读取 `_id`；管理员权限仍执行现有完整校验，鉴权查询另计，不能把两次云函数调用等同于两次数据库读取。每个请求的 10 秒定时器仅用于超时释放，在请求完成或离开前台时清理，不是轮询周期。页面订阅只在内存中分发状态，页面隐藏或卸载后解除订阅。

因此，管理员在另一台设备处理后，用户停留前台或只切换页面不会自动获取新提醒；下次打开或从后台返回时获取最新状态。查看反馈页面仍会正常读取处理结果。数据库查询性能依赖发布步骤中的索引；本地测试只能验证调用频率与行为，不能代替线上耗时测量和索引检查。

删除成功后也会重新读取管理员提醒；被删除的反馈不再计入管理员待办或用户未读结果，其余反馈和同步异常继续按原规则提醒。用户端在原有刷新时机获取删除后的提醒状态。

## 数据与权限

新增 `feedback` 集合，仅通过云函数读写。调用者身份取自微信 SDK 上下文，不接受客户端传入的用户身份或管理员标记。用户只能读取自己的反馈；管理员查询与处理沿用 `adminManager` 的现有学号权限校验。

记录包含 `ownerOpenid`、提交时的 `nickname` / `studentNumber`、`content`、`contact`、`status`、`reply`、`createdAt`、`updatedAt`、`handledAt`、`handledBy`、`unreadForUser`。时间以 UTC ISO 字符串保存，页面按北京时间显示；用户端返回字段不包含用户 OpenID 或处理人 OpenID。状态为 `pending`、`processing`、`resolved`。

`unreadForUser` 为布尔值，提交时为 `false`，首次处理完成或修改已处理反馈的回复时设为 `true`，用户确认已读或管理员重新打开反馈时设为 `false`。缺少此字段的旧记录按已读处理，不追溯点亮历史处理结果；旧记录之后重新处理或修改已处理回复，按同样规则产生新提醒。

提交通过用户身份与 `requestId` 生成固定文档 ID，并在事务内检查，避免网络重试、重复点击产生重复反馈。管理员保存携带读取时的 `expectedUpdatedAt`，事务内再次检查版本；其他管理员已修改时拒绝覆盖，提示重新加载。正文、联系方式与新增或修改的回复在云端进行文本安全检测；检测失败不写入。

删除接口同样先校验云端管理员权限，再在事务内检查反馈 ID 与 `expectedUpdatedAt`。记录已有新修改时返回 `CONFLICT`，管理员需重新加载后再确认删除。记录已不存在时按删除成功返回，支持网络响应丢失后的安全重试；删除不会创建集合，普通用户没有删除接口。

读取反馈列表本身不改变已读状态。页面成功显示结果后，携带实际显示的反馈 ID 和 `updatedAt` 确认已读；服务端在事务内检查记录归属、已处理状态和版本，仅清除匹配版本的未读标记。管理员在用户读取期间更新回复时，新版本保留未读，避免并发更新被误清除。确认已读不改变 `updatedAt`；失败时保留未读，下次成功加载结果时可重试。

## 接口

参数均与 `type` 同级。接口返回 `{ success, data }`，失败返回 `{ success: false, code, error }`。

| 云函数 / 操作 | 参数 | data |
| --- | --- | --- |
| `meditationManager / submitFeedback` | `content, contact?, requestId` | `{ feedback }` |
| `meditationManager / getMyFeedback` | `cursor?, limit?` | `{ feedbacks, nextCursor }` |
| `meditationManager / getFeedbackAlert` | 无 | `{ hasUnreadFeedback }` |
| `meditationManager / markFeedbackRead` | `feedbacks: [{ feedbackId, expectedUpdatedAt }]` | `{ markedCount }` |
| `adminManager / adminListFeedback` | `status?, cursor?, limit?` | `{ feedbacks, nextCursor }` |
| `adminManager / adminUpdateFeedback` | `feedbackId, status, reply, expectedUpdatedAt` | `{ feedback }` |
| `adminManager / adminDeleteFeedback` | `feedbackId, expectedUpdatedAt` | `{ feedbackId, deleted: true }` |
| `adminManager / getSyncAlert` | 无 | 管理员：`{ isAdmin: true, hasErrors, hasFeedback }`；非管理员保持 `{ isAdmin: false, hasErrors: false }` |

列表每页默认 20 条，最多 50 条；`nextCursor` 为空表示没有下一页。管理员列表支持 `all`、`pending`、`processing`、`resolved` 状态筛选。用户和管理员返回的反馈记录均包含布尔值 `unreadForUser`。已读确认每批最多 50 条，不接受重复 ID；不存在、不属于本人、版本已变化或已读的记录跳过，`markedCount` 为本次实际标记数量，重复确认不会重复计数。

提醒接口只返回是否存在的标记，不返回反馈内容或联系方式。`getFeedbackAlert` 使用服务端身份查询本人的 `status: 'resolved'`、`unreadForUser: true` 记录，`hasUnreadFeedback` 不受列表当前页限制。`getSyncAlert` 的 `hasFeedback` 表示存在待处理或处理中的反馈，`hasErrors` 表示同步异常。同步异常和待处理反馈独立检查，单个来源读取失败不会遮蔽另一个已确认的管理员提醒；缺少集合按暂无提醒处理，其他读取失败且没有已确认提醒时返回错误，不假报无事。客户端也独立合并管理员提醒与本人未读结果，避免一个接口失败遮蔽另一个已确认的提醒。

## 发布

1. 在目标云环境创建 `feedback` 集合，客户端安全规则设为 `{ "read": false, "write": false }`，所有访问走云函数。首次读取尚未创建的集合返回空列表；首次提交可在明确的“集合不存在”错误下创建空集合，但不会替代发布时的安全规则和索引配置。
2. 建立以下非唯一复合索引，等待可用：

   | 用途 | 字段与方向 |
   | --- | --- |
   | 管理员全部反馈 | `createdAt` 降序、`_id` 降序 |
   | 本人反馈 | `ownerOpenid` 升序、`createdAt` 降序、`_id` 降序 |
   | 管理员状态筛选 | `status` 升序、`createdAt` 降序、`_id` 降序 |
   | 本人未读处理结果 | `ownerOpenid` 升序、`status` 升序、`unreadForUser` 升序 |

3. 部署 `meditationManager` 和 `adminManager`，包含新增的 `feedback.js` 与 `config.json` 中的 `security.msgSecCheck` 权限；保留现有管理员配置。两个部署目录各有同一份反馈模块，因为云函数不能引用相邻部署目录的文件。
4. 发布小程序。验证用户提交后管理员在刷新时机看到底部“我”和“当前版本”红点，管理员处理完成后自身待办提醒更新、提交者在刷新时机看到底部“我”和“意见反馈”红点，提交者进入反馈页看到结果并确认已读后反馈入口红点消失，底部红点随剩余提醒更新。另需验证两个入口红点按各自来源独立显示和清除、分页中尚未显示的结果保持未读、修改已处理回复再次提醒、无变化保存不重新提醒、重新打开后撤回结果提醒、管理员本人未读结果与管理员待办合并，以及普通账号无法调用管理员反馈接口。

本地回归命令：`npm run test:feedback`、`npm run test:admin`、`npm test`。真机需核对登录返回、长文本、键盘与分页交互。本地代码修改不代表已部署云函数或发布小程序。

删除功能发布时需重新部署 `adminManager` 并更新小程序，无需新增集合或索引。验收取消删除、确认删除、网络失败重试、并发修改冲突、非管理员拒绝，以及删除后管理员列表、用户列表和对应红点的变化。
