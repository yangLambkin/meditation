# 团队按来源接入 bijing-data

新建团队由小程序使用 `wx.request` 直连 bijing-data 的 `/api/openapi/teams`，不调用团队云函数创建。线上现有云函数保持不变。原团队 ID 保持不变，资料、成员、邀请和静坐统计继续走原微信数据库；不迁移历史团队，不双写。

新平台团队对小程序使用 `bijing_<id>`，其他平台成员使用 `bijing_member_<memberId>`，当前操作者映射为当前微信 OPENID。路由由 ID 决定，不采信客户端 `source`。新团队的详情、编辑、解散、成员操作、邀请加入、报表、历史及成员记录全部由 OpenAPI 提供，失败不回退微信写入。

## 功课标签和统计

创建时选择 `sitting` 静坐觉察、`walking` 走路觉察、`instant` 即刻觉察、`learning` 熏习、`kindness` 日行一善或 `clapping` 禅拍，之后不可更改。列表、详情和邀请显示类型标签；目标、统计、提醒和记录按分钟／次／件显示。旧团队默认静坐。

新团队统计读取 data 的个人功课明细，未同步到 data 的微信历史不会自动出现；按北京时间 02:00 切换练习日。为兼容既有页面，小程序适配器的 `dailyGoalMinutes`、`todayMinutes` 等旧字段名保存对应功课的实际数量，另带 `practiceType`、`unit`。成员记录和历史明细使用 data 的不透明游标。

## 身份、重试和编辑

直连复用功课记录已有的过渡 OpenAPI 方案：`teamConfig.js` 复用 `practiceConfig.js` 的 `baseUrl` 和通用服务凭据；`practiceAuth.js` 提供当前微信账号绑定的学号与绑定版本。请求前后核对当前账号和绑定，不接受客户端表单中的操作者或权限。创建、加入及成员数据需绑定本人学号；未绑定者可使用通用凭据浏览公共预览。

通用凭据可以从小程序包中提取，学号与绑定版本头不证明本人身份，data 不验证微信云端绑定；这与现有功课直连的过渡信任边界相同。data 查询唯一启用成员并强制普通成员权限，检查团队成员关系及团长／副团长权限，不提供平台管理员操作。`BIJING_TEAM_ACCESS_TOKEN` 仅保留旧服务端转发兼容，不放进小程序，也无需为本次直连配置它。

接受新团队邀请时，若本机没有可用绑定，先通过既有 `getUserProfile` 恢复当前微信账号的学号状态；仍未绑定时只提示“尚未绑定学号”，不自动跳转。已确认的邀请按账号保留，加入成功后才清除。邀请弹窗复用缓存邀请前重新读取团队，核对当前成员资格及团长／副团长权限；核验失败时停止分享并提示刷新。

创建前按账号、完整表单持久化 `operationKey`，失败重试复用同一个 `Idempotency-Key`，成功后清除。成功响应必须包含 `bijing_<正整数>` ID、正确来源与提交时的功课类型；不再用客户端草稿补齐缺失的服务端确认。小程序下载现有内容审核返回的同一份云头像，再通过 `wx.uploadFile` 直接上传 data；data 对规范化图片生成稳定地址，避免头像重传改变幂等载荷。编辑提交页面看到的 `expectedVersion`，交接提交原团长，过期页面由 data 拒绝。

微信 `wx.request` 不支持 `PATCH`，新团队编辑使用 `PUT /api/openapi/teams/{id}`；须先发布支持 `PUT` 的 data 版本，服务端保留原 `PATCH` 入口兼容已有调用方。

## 发布配置

1. 先发布包含团队 OpenAPI 及直连凭据支持的 bijing-data 版本（契约见该仓库 `docs/openapi-teams.md`），按该仓库说明准备团队数据表。保留已有通用 OpenAPI 凭据与 OSS 配置。
2. 团队接入不修改或部署任何云函数，`teamManager` 保留接入前的微信团队实现。小程序直连地址沿用功课配置：测试 `https://data.bjzl.net.cn`，生产 `https://data.bijing.life`。将对应域名加入微信 request、uploadFile、downloadFile 合法域名。
3. 发布小程序并验证头像、邀请及长名单提醒导出。data 未部署、凭据或网络异常时，新建明确失败，不降级到微信创建。新旧列表分别读取后合并，单个来源失败保留该来源缓存并显示提示。
4. 使用已绑定账号验收：旧团队读取与管理、新团队创建／超时重试、六类标签和单位、邀请多人加入、角色调整及交接、解散、月份和游标分页。旧团队和微信个人历史不执行迁移。

`npm run test:team` 覆盖来源路由、请求归属、OpenAPI 参数与结果适配、稳定创建请求、旧团队回归、功课单位、邀请和分页。实际发布前仍需 data 部署和微信真机联调；本次代码调整不执行部署或云函数更新。

## 同期静坐编辑的云函数范围

2026-11-05 的静坐完整编辑单独需要更新 `meditationManager`，用于原记录、统计和历史日期同步待办的事务保存。`teamManager` 与 `bijingSync` 不随本次编辑更新，不增加编辑专用的即时同步接口。

编辑影响的两个日期中，已结束的日期均写入既有同步待办，包括移走最后一条记录后的零总量；未结束的当天沿用次日 02:00 上传。历史待办由既有定时核对与修复处理，保存成功不表示必经日汇总已经更新。该方案依赖线上已有待办修复版本及触发器启用；现有核对时段为北京时间 03:00—10:00，10:00 后编辑的历史汇总可能要等次日核对。
