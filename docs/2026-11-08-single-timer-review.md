目标：以 `85fc7c50a21bf0398303d5ed0d8c122ed2ca3956`（V3.0.7、V3.0.8 的直接父提交）为唯一实现，保留模块化，仅增加来电/闹钟不中断计时。管理员切换和云配置代码已移除。

接口、文件边界和完整流程见 [模块说明](../miniprogram/modules/timer/README.md)，历史来源见 [SOURCE](../miniprogram/modules/timer/SOURCE.md)。

## Review 结果及修改

| 检查项 | 结论与处理 |
| --- | --- |
| 模块边界 | 页面只引用 `modules/timer/index`、模板和样式；App 转发生命周期；记录与日签复用宿主服务；主包直接加载唯一实现 |
| 历史行为 | 保留 5 秒起坐等待、起坐后引导、固定铃声、暂停/继续/重置、推荐时长、心得与日签流程；原音频 SHA-256 一致 |
| 中断与主动退出 | 保留同一 sessionId 和时间戳；主动关闭按旧版结算；来电时间计入运行时长，手动暂停不计入；音频抢占与真正 AppHide 分别处理 |
| 事件顺序 | 覆盖 AppHide 与音频中断交错、页面卸载、返回前台、音频延迟恢复；过期倒计时只触发一次完成，旧起坐快照不能覆盖收坐 |
| 普通冷启动 | 修复中断标记残留，恢复后后续普通检查点不会被误判为仍在来电中；无中断标记仍按历史最后检查点结算 |
| 保存失败 | 修复独立草稿写入失败时遗漏终态内嵌草稿；成功保存同时确认两个副本；保留同一身份重试 |
| 持久化恢复 | 修复离页正计时已保存但终态写失败时恢复旧运行状态的问题；返回前台重试终态；读失败不能当作空存储覆盖新会话 |
| 通知与幂等 | 修复完成通知在反复进入页面时重复展示；记录层按 sessionId 幂等键去重，退出、重试不会创建第二次静坐 |
| 可用性 | 计时不依赖配置网络请求；音频/亮度/常亮等附属操作失败不应中止会话；存储异常有内存交接及终态草稿恢复 |
| 清理与回收 | 卸载时释放定时器和监听；被动回收先交接正计时，主动离页沿用旧版结束规则 |
| 权限与范围 | 无新增服务器接口、管理员权限或集合；管理员切换界面和接口已撤除；记录授权沿用宿主 |
| 多设备 | 保留安全区、窄屏、宽屏、短屏适配和 SVG 图标；音频中断 API 做存在性判断；模拟器验证一套页面与两种计时模式 |

## 后续建议与已知边界

1. 发布前用 iPhone 与 Android 真机覆盖起坐等待、起坐播放、引导、静默计时、手动暂停和接近截止时刻的电话/闹钟中断，同时测试耳机和扬声器。结束时间应准确，完成记录应只有一条。
2. 系统占用音频或挂起 JS 时，无法保证到点立即播放；返回后校正时长并处理提醒。缺少 hide 原因的老微信按保留计时处理，主动切后台也可能继续，这是避免误结束来电的兼容选择。
3. 无任何中断通知的进程强杀、清除缓存和持续存储故障无法保证跨进程恢复；应用不宣称后台常驻。普通冷启动仍遵循旧版检查点规则。
4. 保留历史页面的控件结构。本次以行为回归为范围；后续可单独为开始/暂停/结束等 `view` 控件补齐无障碍按钮角色与朗读名称，并在大字体与横屏真机复核。

本次只修改工作区代码，没有发布小程序或部署云函数。
